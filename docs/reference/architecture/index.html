架构差异与迁移清单

目标仓库核对基线为 33998b5。

对齐原则​

以 TAP 7071640a 的应用组织和交互合同为参考。统一 SDK → CLI → Agent 的依赖方向、工作台协作、权限、存储与独立工具接入；科学算法、实验数据格式和任务验收仍归各项目自己的实现。门户继续承担账号、空间与实例路由，不需要机械复制科学 SDK。

这是 2026-11-01 的源码差异审计与待办，不是已经迁移或通过运行回归的声明。本次只实现文档站统一。三个实验项目的未提交桌面客户端工作未纳入基线。

禁止跨仓共享运行配置、凭据、工作区或端口。后续若吸收 nanobot 官方或 fork 改动，须同轮更新该仓 VENDORED.md 与上游同步审计，不能拿本页代替上游记账。

当前差异​

能力当前证据与差异迁移顺序
分层与命令tpx/、tpxtpx/catalog.py、tpxtpxtpx/ 已分层；实验处理使用冻结计划保留现有科学命令合同，不改成 TAP 命令名称
工作台持久化workbench/runtime.py、layout.py 已实现 scope、版本冲突、动作 claim/resolve 与重启不确定状态先回归已有保护，再适配 TAP 后续草稿兼容修复
全局工作权限未找到 TAP 的 WorkSettings 与 workbench.permission 对应实现P1：逐次确认、自主执行、撤销、排队动作重新判权一起迁移
HTML 应用外观webui/src/components/workbench/HtmlApp.tsx 尚无 TAP 的 theme/language context 推送P1：同步主题和语言，切换外观不重置科学表单
存储位置有 OSS 配置及完整下载；未见 TAP 的 storage/local.py、user_scope.py 与统一位置前端P2：位置发现、目标目录选择、只读边界和输出定位成套适配
DAG 与产物没有 TAP 的具名端口数据流模块；TPX 已有自己的处理计划与结果P3：先映射 TPX 工件和依赖，再评估加入通用 DAG
门户隔离portal-context.ts 和 docs/portal-managed.md 已有实例绑定保留并补跨账号、过期会话与文件访问回归

实施与验收​

  1. P1 先对齐权限、草稿和界面上下文。回归跨对话/工作区隔离、冲突保存、撤销后的排队操作、重启后的不确定动作；不允许自动重放未知执行结果。
  2. P2 再对齐存储和门户工具。验证路径越界、符号链接、只读挂载、跨账号访问、同名输出保护、完整传输哈希和显式分享。打开或预览文件不能触发模型工作或自动上传。
  3. P3 最后引入适用的数据流能力。验证单文件/列表/目录端口、数量限制、旧残留产物排除、输入变更失效及完整 lineage。保留各科学服务的检查、取消和人工验收。
  4. 每批只修改当前仓，运行对应后端回归与前端构建，同轮更新手册，再提交到 cursor。部署须另外确认镜像、挂载和原有数据保留。
