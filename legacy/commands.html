READ THIS FIRST

命令目录不是自动 Pipeline

tpdtpd 负责参数和文件适配，科学计算位于 tpx SDK。某些叶命令创建新工件，某些还会更新实验配置；执行前应查看叶命令帮助，完成后应阅读当次报告。

参数界面只按真实 parser 区分“必须给值”和“已有默认值”：没有单独的高级或可选分组。有默认值的参数可折叠，但界面必须显示默认值；完整逐项说明见 36 条叶命令中文参考。

TTY 中的 tpdtpd --list 保留交互命令菜单；非 TTY 或 --list --plain 给出确定性的文本目录。阶段命令默认输出适合人读的报告；机器调用应在首次执行叶命令时加 --json 并读取 stdout，不要为了取得 JSON 重跑写文件或改配置的 action。

下方示例来自当前 registry，只用于展示语法。路径、物种、区间、阈值、质量与 BET 必须换成真实且已复核的值；未知或未测量值应省略，不能填成 0。

DOC

independent documentation

独立文档入口

tpxdocs 只列出和读取离线学习资源；它不属于 tpdtpd manifest，也不会打开或修改实验。

DOC.1

tpxdocs

浏览独立的离线文档目录，阅读 TPD SOP、网页教程、技术文档与教学图片。

输入
list 无需实验文件；show RESOURCE_ID 只接受目录中列出的资源。
输出
离线资源目录或一项已核验资源；机器调用可显式请求 --json。
你来决定
当前实验需要阅读哪项资料；文档协议不属于方法 manifest，也不会执行科研命令。

安全入口tpxdocs list

查看离线文档目录 
$ tpxdocs list
$ tpxdocs show TPDsop/index.md
01

experiment creation

新建实验

只负责根据已知实验事实创建新的 schema 4 TOML；不属于当前实验的配置检查。

01.1

init

从实验事实创建不预设目标物种的 schema 4 TOML。

输入
新配置路径、实验名、RGA CSV、温控日志；质量与 BET 可选。
输出
新的 TOML：reference inherited-unreviewed、vacuum AMU→常数电流初值、2/18/28/40/44 五通道 identity fragmentation；后续可逐 AMU 审核纯指数。
你来决定
名称与路径是否属于同一次实验；未测质量、BET 或 m/z 14 不能填成 0。

先看参数tpdtpd init --help

查看当前 registry 示例 
$ tpdtpd init experiment.toml \
    --name '20260804#3' \
    --rga-csv raw.csv \
    --temperature-log temperature.txt
02

configuration check

配置检查

只读核对当前配置、原始数据、处理谱系与命令状态；不包含文档学习或新建实验。

02

config

按子命令分别检查 schema 4 配置、原始数据概况、ProcessingRecord 谱系或命令证据状态。

输入
三条子命令都严格解析 schema 4 TOML。inspect 始终读取配置直接引用的 RGA 与温控日志，可重复指定 --require-mass；provenance 不读取这两份原始数据，只核验 ProcessingRecord 输出；status 不消费时钟容差或 AMU 参数，但可能读取或哈希当前记录绑定的证据/来源文件。
输出
inspect 的配置与原始数据概况、provenance 的处理谱系核验，或 status 的命令就绪度与审核门禁；全部只读。
你来决定
必需 AMU 是否来自下游真实需求，以及实际通道、时长、点数与温度范围是否符合采集记录。

先看参数tpdtpd config inspect --help

查看 3 个子命令与示例
  • inspect读取配置及其引用数据的概况。
  • provenance严格加载 schema 4 后，核验并展示完整 ProcessingRecord 谱系。
  • status严格加载 schema 4，展示命令就绪度、证据完整性与审核门禁；按当前记录需要读取或哈希其证据/来源文件，不能当作纯配置门禁。
$ tpdtpd config inspect experiment.toml \
    --require-mass 28 --require-mass 40
03

process one decision at a time

每次只处理一个判断

建议、复核和执行分开。输入文件由研究者显式指定，程序不根据文件存在性猜测上一阶段。

03.1

temperature

建议升温边界、拟合已复核温程，再把模型应用到 RGA 时钟。

输入
suggest/fit 使用配置引用的温控日志与人工边界；align 只把显式选择的 .tpxmodel 作为温度模型输入，并使用当前 RGA、温控源及本次时钟策略。
输出
按子命令产生边界建议、拟合审阅 CSV、可重载 TOML 模型、拟合记录或温度对齐电流表。
你来决定
边界、模型适用性、时间偏移与越界规则；suggestion 不等于 reviewed 结果。

先看分支tpdtpd temperature --help

查看 3 个子命令与示例
  • suggest检查温控日志并建议升温边界。
  • fit拟合显式、人工复核的升温区间。
  • align把已复核温程模型应用到 RGA 时钟。
$ tpdtpd temperature suggest experiment.toml
03.2

vacuum

从完整标气采集为每个 AMU 独立审核常数或两锚点纯指数真空模型，再显式写入并逐行扣除。

输入
show 读取 experiment TOML 与完整 HAL RGA CSV，并要求无默认值的 --baseline-model constant|exponential。constant 每 AMU 恰好一个窗口；exponential 每 AMU 恰好两个按输入顺序排列、严格分离且不重叠的首尾窗口。
状态/输出
show 写 records/vacuum_baseline_review.json 与完整信号/模型/窗口复核图；指数图另含扣除后完整信号与零线，不修改 TOML。set --current 写常数；互斥的 set --review-record 验证 config/raw SHA-256 后接受整组模型。subtract 写 m*_input_a / m*_baseline_a / m*_signal_a、ProcessingRecord，并沿用 calibration_vacuum.csv / desorption_vacuum.csv / vacuum.csv 默认名。
你来决定
每个信号的模型、严格窗口、mean/median 和最少点数。指数要求 I1 > I2 > 0，纯指数最终趋近 0；程序不回退模型、不裁剪负值，也不自动判断稳定或接受。

先看分支tpdtpd vacuum --help

查看 3 个子命令与示例
  • show审核常数或按 b(t)=I1 exp[-k(t-t1)] 拟合的纯指数；记录锚值、k/tau、残差、窗口斜率等机械证据，不写 TOML。
  • set用互斥的 --current 或 --review-record 写入；新模型仅替换同 AMU，其他 AMU 保留，因此可混用两种模型。
  • subtract指数只接受绑定 raw 或可验证同源 aligned 子表；缺时间、来源不符或越界都会拒绝。
$ tpdtpd vacuum show experiment.toml \
    --input calibration.csv \
    --baseline-model exponential \
    --signal-window 28 1 3 \
    --signal-window 28 24 27.5 \
    --estimator median

$ tpdtpd vacuum set experiment.toml \
    --review-record records/vacuum_baseline_review.json
03.3

response_zeroing

在 aligned fragmentation 之后按物种从研究者选择的任意稳定无峰窗口估计常数零偏；窗口可以在升温前，也可以在峰后尾段。先看完整曲线与扣除前后窗口，再一次接受并应用当前输入对应的全部零点。

输入
heating_desorption_aligned fragmentation.correct 的已验证 resolved-species 表。
状态/输出
estimate 把一个物种的坐标、窗口、估计器、offset 与输入身份写入 experiment TOML，并默认生成 records/<target>_response_zeroing_estimate.json 和输入旁的四面板审核图；状态仍是 pending。apply 没有 target 参数，它会按原输入重算并核对全部当前定义；显式运行 apply 就是共同接受这些匹配定义，并输出 response_zeroed.csv。
你来决定
每次 estimate 的 target、选择坐标、稳定无峰窗口、median/mean 和最少点数。尾段优先用 program_time_min 精确锁定连续时段；程序不会自动替你选择“最低且稳定”的区域。

先看分支tpdtpd response_zeroing --help

查看 2 个子命令与示例
  • estimate用 program_time_min、acquisition_time_min 或 temperature_fit_c 选择一个连续稳定无峰窗口；温度带若命中多个不连续时段会拒绝。
  • apply从 experiment TOML 读取所有与当前输入匹配的 estimate，按窗口重算 offset 后一次应用；没有 estimate 的 resolved species 原样保留。
$ tpdtpd response_zeroing estimate experiment.toml \
    --input out/desorption_fragmentation.csv --target CO \
    --coordinate-column program_time_min --zero-window 30:40 \
    --estimator median --minimum-points 64 \
    --record-output out/records/co_response_zeroing_estimate.json

$ tpdtpd response_zeroing apply experiment.toml \
    --input out/desorption_fragmentation.csv \
    --output out/response_zeroed.csv

vacuum 是 fragmentation 前逐 AMU 常数/指数扣除；calibration background 只计算标气平台增量；response_zeroing 是 fragmentation 后逐物种常数修正；integration baseline 才是定量后的面积参考线。四者不能互换。历史 AMU 域 preheat 案例也不是当前命令语义。

03.4

reference

查看、修改并显式接受内标气身份、流量和标准状态。

输入
TOML 中完整 reference 记录；set 还需至少一个实际变更值。
输出
含当前/已接受指纹与有效性的只读状态报告、pending 配置更新，或指纹绑定的 accept 记录。
你来决定
继承的 Ar/25 sccm/标准状态是否属于本实验；只有 current 状态能用于绝对定量。

先看分支tpdtpd reference --help

查看 3 个子命令与示例
  • show显示完整值、当前/已接受指纹、review validity 与绝对定量门禁。
  • set把变更后的完整 reference 状态保存为 pending。
  • accept传回 show 展示的当前指纹；写回前比较配置快照，发现并发改动则拒绝覆盖。
$ tpdtpd reference show experiment.toml
$ tpdtpd reference accept experiment.toml --expected-reference-gas-fingerprint FINGERPRINT_FROM_REFERENCE_SHOW
03.5

fragmentation

复核“观测 AMU × 物种”矩阵，再把一张显式观测质量电流表求解为物种电流。

输入
TOML 中当前运行时矩阵，以及一张含规范 m{AMU}_signal_a 或原始 m{AMU}_raw 列的显式观测表；严格模式要求配置中的每个 AMU 都存在。无父记录或 raw 表只适合独立矩阵诊断；正式处理链应先完成 vacuum，并且只有继承 SHA256 匹配父 ProcessingRecord 和对应 artifact role 的结果，才能进入后续 calibration / quantify。
输出
矩阵报告、配置矩阵，或含本步 m{AMU}_input_a 与 {species}_resolved_a 的新 CSV。校准/脱附支路默认分别为 calibration_fragmentation.csv / desorption_fragmentation.csv，角色无法验证时才回退 fragmentation.csv。表头不编码处理历史；只有匹配的 ProcessingRecord、角色/阶段与 SHA-256 才证明来源。
你来决定
行列标签、系数与可解性；单位阵也应作为一次显式处理保留。

先看分支tpdtpd fragmentation --help

查看 3 个子命令与示例
  • show查看 TOML 中当前运行时矩阵及来源；新建配置可能仍是默认 identity mapping。
  • set原子保存研究者复核的运行时矩阵。
  • correct对一张显式观测电流表求解物种电流。
$ tpdtpd fragmentation show experiment.toml
03.6

calibration

建议吸附校准区间，再从真实配气组成拟合目标物种/参比响应系数。

输入
完整采集的 vacuum → fragmentation 表、目标物种/质量、区间与真实配气比。
输出
suggestion、provisional preview 指标，或 reviewed fit 系数/指纹；preview/fit 的科学状态写入 experiment TOML，详细证据默认进入 records/，不再生成单行 CSV。
你来决定
校准背景、稳定平台、目标质量与实际混合比例。

先看分支tpdtpd calibration --help

查看 3 个子命令与示例
  • suggest建议给气前背景区和吸附稳定平台。
  • preview计算指标/图但不提交 reviewed calibration；--compare 并列 suggestion、preview 和 active reviewed。
  • fit拟合 expected/measured 响应并保存复核结果。
$ tpdtpd calibration suggest experiment.toml \
    --input out/calibration_fragmentation.csv \
    --target CO --target-mass 28
03.7

quantify

把已处理的物种电流逐步检查为相对响应、组成、流量与摩尔速率。

输入
来自已验证 vacuum → fragmentation 或 vacuum → fragmentation → response_zeroing aligned 脱附链的物种响应，以及匹配当前 vacuum / fragmentation 指纹和处理记录的 active reviewed calibration。
输出
四个叶命令依次各写一张 long-format CSV：relative.csv → composition.csv → flow.csv → rate.csv。每行用 target_species 保留物种身份，多物种共享同一组表。
你来决定
一个或多个 target species 与最低参比比例；--target CO,NH3 和中文逗号 --target 'CO，NH3' 都受支持。当前没有 quantify all 或 combined/split 布局。

先看分支tpdtpd quantify --help

查看 4 个子命令与示例
  • relative目标电流除以配置的参比电流。
  • composition用目标校正因子换算摩尔比。
  • flow把目标/参比摩尔比换算为目标流量（sccm）。
  • rate把 sccm 换算为摩尔速率（µmol min−1）。
$ tpdtpd quantify relative experiment.toml \
    --target CO,NH3 --input out/fragmentation.csv

$ tpdtpd quantify composition experiment.toml --target CO,NH3 --input out/relative.csv
$ tpdtpd quantify flow experiment.toml --target CO,NH3 --input out/composition.csv
$ tpdtpd quantify rate experiment.toml --target CO,NH3 --input out/flow.csv
03.8

normalize

在保留绝对摩尔速率的同时，增加按样品质量和可选 BET 面积归一化的列。

输入
含 response_umol_min 的 long-format rate.csv；质量/BET 默认来自 TOML，CLI 可显式复核覆盖。
输出
保留坐标、绝对响应和本步归一化结果的新 normalized.csv。
你来决定
质量与 BET 来源；与 TOML 冲突时只有 --reviewed-sample-override 才继续。

先看参数tpdtpd normalize --help

查看当前 registry 示例 
$ tpdtpd normalize experiment.toml \
    --input out/rate.csv \
    --mass-mg 60
04

analyze checked curves

分析已检查的曲线

统一从 normalized.csv 出发：先预览并接受分析基线，再分别运行候选峰或正式面积动作。基线、候选摘要和面积进入 experiment TOML，逐点证据进入 records/*.json，不再生成分析 CSV。

BEGINNER GUIDE 同一条曲线，为什么要分成看曲线、算吸附量、找峰温？ 打开曲线分析入门：真实列名、单位、输出形状与人工判断点 →
04.1

integration baseline

先预览一条主观分析基线，人工看图后再接受同一 normalized 输入和定义；不物化基线扣除 CSV。

输入
normalized CSV、规范绝对响应、程序起点、审核温区、基线模型/来源和估计量。
状态/输出
preview 把 pending 可复算定义写入 [integration_baseline.<target>]，详细证据默认写 records/<target>_integration_baseline_review.json，审核图写在输入旁；accept 核验输入与定义后改为 reviewed，并写 acceptance JSON。两步都不写 CSV。
你来决定
target、模型、取样范围和审核温区；accept 是独立人工门禁，不会因 preview 成功而自动发生。后续动作从 normalized 表和 reviewed 定义即时复算。

先看分支tpdtpd integration baseline --help

查看 preview 示例 
$ tpdtpd integration baseline preview experiment.toml \
    --input out/normalized.csv --target CO \
    --start-c -180 --end-c 65 \
    --baseline linear --baseline-left-range-c=-180:-170 \
    --baseline-right-range-c=55:65 --baseline-estimator median \
    --linear-on time

$ tpdtpd integration baseline accept experiment.toml \
    --input out/normalized.csv --target CO
04.2

integration areas

从 normalized 表与已审核 TOML baseline 即时复算基线扣除响应，选择一个或多个具名温区，先预览，再沿程序时间正式积分。

输入
normalized.csv、target、稳定的 result-id、reviewed baseline、具名温区、负值/边界规则和可选的显式复核峰位；质量/BET 默认来自 TOML。未审核找峰候选不参与计算。
状态/输出
--preview 只写 records/<result-id>_areas_review.json 与审核图，不写正式面积；正式运行写 [peak_integration.<result-id>] 与 records/<result-id>_areas.json。两种模式都不写 summary 或逐点 CSV。
你来决定
每个积分温区、名称、稳定且防撞的 --result-id、负值与边界规则；--peak-position 才记录人工复核的 Tp，省略时只记录区间内最大积分响应采样点 Tmax。

先看参数tpdtpd integration areas --help

查看当前 registry 示例 
$ tpdtpd integration areas experiment.toml \
    --input out/normalized.csv --target CO \
    --start-c -160 --end-c -90 --interval-name peak-1 \
    --interval peak-2 -60 20 \
    --result-id co_integration --preview

$ # 同一样品两峰共享一个 result ID；人工确认后用同一参数去掉 --preview，正式面积进入 TOML + records/co_integration_areas.json。
04.3

integration peaks

从 normalized 表与 reviewed baseline 复算基线扣除响应，在独立温区和参数假设下寻找候选峰、建议边界与可选形状诊断。

输入
normalized.csv、target、稳定的 result-id、basis、温区、峰数、最小间隔、总宽平滑窗和 reviewed baseline。
输出
候选摘要写入 [integration_peaks.<result-id>]，逐点证据默认写 records/<result-id>_peaks.json，审核图写在输入旁；不生成 peaks/curve CSV。谷底边界始终标记为未经审核且未用于积分。
你来决定
峰参数与最终积分区间；可选 Gaussian seeds 只做无面积的重叠形状探索。

先看参数tpdtpd integration peaks --help

查看当前 registry 示例 
$ tpdtpd integration peaks experiment.toml \
    --input out/normalized.csv --target CO --result-id co_candidates \
    --basis absolute \
    --program-time-start-min 0 --start-c -180 --end-c 60 --count 2 \
    --minimum-separation-c 20 --smoothing-window-c 6 \
    --plot-output out/co_candidates_peaks.png
05

review and publish

复核与发布

图是检查和交流的产物；它不替代产生曲线时使用的参数、单位与来源记录。

05.1

plot

分别复核原始 MS、温程拟合、校准区间、单实验完整定量响应，或比较多个实验的完整响应与正式峰结果；可独立调整只作用于成图的平滑、标题和字体。

输入
明确的数据表和图类型；response 读取 normalized.csv，还需明确 total 或 baseline-subtracted 口径及纵轴 basis；baseline-subtracted 由同一表与 TOML 中 reviewed baseline 即时复算。comparison 至少重复两次 --series LABEL CONFIG INPUT。
显示参数
raw、temperature、calibration 用 --smoothing-window-min，response、comparison 用 --smoothing-window-c；两者都是 local-quadratic 物理总窗宽，默认 0。--title auto 自动命名，也可自定义；--font-family auto 与 --font-weight auto 可显式覆盖，字体不存在时拒绝静默回退。
输出
response 默认画完整程序升温支路、核验 TOML 正式峰结果并标注当前 basis 面积，文件名含 target、response mode、basis 与 range；comparison 默认输出 absolute、mass-umol、BET 三面板且必须显式给新文件路径。峰位与单位以 MathText 显示真正的上下标，不依赖 LaTeX。
你来决定
画哪一种数据、物理纵轴、只用于显示的平滑总窗宽、标题、字体、是否保留正式峰标注，以及比较系列标签与输出路径。平滑不会改写 CSV/TOML，也不会改变温程拟合、校准因子、基线、正式峰位、峰面积或积分区间；自动画图和哈希核验都不等于人工科学接受。

查看 5 个子命令与示例
  • raw原始质谱信号；可用 min 总窗宽平滑显示线。
  • temperature保留原始测温散点，可选增加显示平滑线；下游拟合温度不变。
  • calibration可平滑目标/内标显示线；审核区间与校准因子不变。
  • response默认完整升温支路，并从 TOML 标注经 SHA-256 验证的正式 Tmax/Tp 与面积。
  • comparison多实验完整 total response 的共享温度轴多面板比较与正式面积表；每条线按自身采样间距换算同一 °C 总窗宽。
