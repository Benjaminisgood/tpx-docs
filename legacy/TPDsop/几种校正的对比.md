# TPD 数据处理关键逻辑：校正、响应标定、定量与峰面积

本文说明 `tpdtpd` 当前数据处理流程中各命令的科学含义、先后顺序、输入输出、数学关系和审核边界。它不是一份只告诉操作者“按哪个按钮”的命令清单；重点是解释为什么必须分成两条数据支路，以及每个工件可以和不可以用于什么目的。

适用版本：TPX 0.8，schema 4。本文使用 `CO` 作为目标物种、`Ar` 作为内标的示例，但程序不会自动认定任何质量数属于 CO 或 Ar。物种名称、观测质量数和碎片矩阵必须来自当前实验的明确配置与实验依据。

## 1. 最终数据流

### 1.1 完整采集（raw/full）校准支路

```text
完整采集 raw CSV
  → vacuum.*
  → fragmentation.*
  → calibration.suggest
  → calibration.preview [可选 --compare]
  → 人工复核
  → calibration.fit
  → TOML 中当前有效的 [calibration.<species>]
```

这条支路的任务是得到目标物种相对于内标的响应校正因子。输入必须保留校准气切换前的目标背景段和通入已知混合气后的稳定平台，因此只能使用完整采集数据，不能用只覆盖程序升温段的 aligned CSV 代替。

### 1.2 程序升温（temperature-aligned）定量支路

```text
temperature.align 生成的 aligned CSV
  → vacuum.*
  → fragmentation.*
  ├─→ 直接 quantify.*
  └─→ [可选] response_zeroing.estimate
       → 人工复核
       → response_zeroing.apply
       → quantify.*
  → normalize
  → integration baseline preview
  → 人工复核
  → integration baseline accept
  ├─→ integration peaks
  └─→ integration areas
       → TOML [peak_integration.<result-id>]
       ├─→ plot response（单样、完整温程、正式峰注释）
       └─→ plot comparison（多样、同图多纵轴）
```

这条支路的任务是把随温度变化的脱附信号换算成逐点摩尔响应，再由研究者决定积分基线、峰区间和最终峰面积。

`response_zeroing` 是 `fragmentation` 之后、`quantify` 之前的可选正式分岔。它不能插入 raw 校准支路，也不能放在 fragmentation 之前。

## 2. 为什么必须保留两条支路

校准数据和脱附数据虽然使用同一套真空电流、碎片矩阵和响应因子，但它们回答的问题不同：

| 数据角色 | 主要内容 | 用途 | 禁止替代的对象 |
|---|---|---|---|
| `full_acquisition` | 完整校准气采集，包含目标背景和混气平台 | 拟合 `calibration` | 不能作为程序升温定量输入 |
| `heating_desorption_aligned` | 已和温度程序对齐的脱附采集 | `response_zeroing`、`quantify`、峰分析 | 不能用于拟合 `calibration` |

程序不靠文件名猜测角色。角色来自可验证的处理记录：

- 对配置中原始 RGA 文件执行 `vacuum subtract`，产物记为 `full_acquisition`。
- `temperature align` 产物记为 `heating_desorption_aligned`；在其上执行 `vacuum subtract` 和 `fragmentation correct` 时继续继承该角色和温度对齐指纹。
- 任意手写、改名或复制的 CSV，即使列名相同，也不能仅凭文件名获得这些科学角色。

因此当前门禁是：

- `vacuum.*` 和 `fragmentation.*` 的数值能力都可处理 raw/full CSV 与 aligned CSV。
- `calibration.*` 只接受 SHA-256 可验证的 `full_acquisition fragmentation.correct` 工件。
- `response_zeroing.*` 只接受 SHA-256 可验证的 `heating_desorption_aligned fragmentation.correct` 工件。
- `quantify.*` 只接受 aligned 的 `fragmentation.correct`，或者它后面的 `response_zeroing.apply` 工件。

## 3. 四类容易混淆的“背景/基线”

它们处理的对象、位置和科学目的完全不同，不能互相替代。

| 名称 | 所在信号域 | 数学动作 | 流程位置 | 目的 |
|---|---|---|---|---|
| `vacuum` 真空电流扣除 | 逐 AMU 质谱电流 | 每个质量通道逐行减去独立常数或 raw-bound 纯指数真空模型 | fragmentation 之前 | 去除仪器/真空系统的质量通道本底 |
| `calibration background` 标定背景 | 完整标气实验的 resolved target response | 计算通入目标气后平台相对通气前背景的增量 | full-acquisition calibration 支路 | 拟合本次 target/reference 响应因子；不作用于脱附曲线 |
| `response_zeroing` 物种响应归零 | fragmentation 解混后、按样品和物种独立审核的响应 | 从明确的稳定无峰窗口估计常数，再从该物种整条曲线相减 | fragmentation 之后、quantify 之前 | 让所选升温前或峰后尾段窗口的 mean/median 成为 0 |
| `integration baseline` 峰面积积分基线 | 已定量或归一化的响应曲线 | 构造 zero/constant/linear/piecewise-linear 基线并相减 | quantify/normalize 之后 | 定义最终峰面积相对于哪条线积分 |

四者都可能在日常语言中被简称为“基线”，但它们不使用同一段数据，也不传递同一个数值。
尤其不能把 calibration background 当作脱附曲线的通用基线。同一样品的两个峰可以共享一个
reviewed integration baseline；这不表示两个样品共享同一 response-zero offset 或其他 baseline 数值。

旧流程中的 `preheat estimate/subtract` 已删除。它原本容易让人误以为是在 fragmentation 之前修正质量通道；当前实现改成了含义更准确的 `response_zeroing estimate/apply`，并明确放在物种解混之后。

## 4. `vacuum.*`：逐 AMU 真空电流校正

### 4.1 科学对象

对质量数为 \(m\) 的输入电流 \(I_m(t)\)，使用当前配置的逐点真空模型 \(B_m(t)\)：

```text
I_m,vacuum-corrected(t) = I_m,input(t) - B_m(t)
```

常数模型的 \(B_m(t)=B_m\)。两锚点纯指数模型使用研究者为该 AMU 选择的首窗、尾窗：窗口内
mean/median 分别为 \(I_1,I_2\)，相应有限样本时间中位数为 \(t_1,t_2\)，于是

\[
B_m(t)=I_1\exp[-k(t-t_1)],\qquad
k=\frac{\ln(I_1/I_2)}{t_2-t_1}.
\]

指数只接受 `I1 > I2 > 0`、`k > 0`，并要求完整 raw 来源范围内预测有限。纯指数最终趋近 0；
程序不回退为常数或线性，不裁剪扣除后的负值。每个 AMU 独立估计；不同 AMU 可以混用两种模型，
同一 AMU 只能有一个。缺失质量通道不会被伪造为 `0 A`，输入中存在但配置未提供模型的通道也不会
被暗中校正。exponential 的 show 输入必须是 experiment 配置的 exact `rga_csv`；constant 可审核
另一份明确给出的完整 HAL CSV。

### 4.2 动作含义

- `vacuum show`：读取完整 raw HAL RGA CSV；必填且无默认的
  `--baseline-model constant|exponential` 决定本次审核模型。constant 每个 AMU 恰好一个窗口；
  exponential 每个 AMU 恰好两个按输入顺序排列、严格分离且不重叠的首尾窗口。输出完整曲线、
  模型和窗口的审核图与 JSON；指数图另含扣除后完整曲线和零线，不修改 TOML。
- `vacuum set`：两个入口互斥。`--current AMU:A` 直接写入人工复核的常数；
  `--review-record JSON` 核验记录、当前 config SHA-256 与当前配置 raw 的 SHA-256 后，原样接受记录中的
  全部模型，避免手抄指数系数。接受后的指数模型以 raw 内容 SHA-256 为采集身份；相同字节的路径迁移
  不会制造另一套身份，任何字节变化都会使模型与下游谱系失效。
- `vacuum subtract`：使用当前逐 AMU 常数/指数模型产生新 CSV，每行保留实际 baseline。

新的审核命令形式是：

```bash
tpdtpd vacuum show CONFIG \
  --input CALIBRATION.csv \
  --baseline-model exponential \
  --signal-window 28 1.0 3.0 \
  --signal-window 28 24.0 27.5 \
  --estimator median \
  --minimum-points 3
```

每个 `--signal-window AMU START_MIN END_MIN` 都在 `acquisition_time_min` 上独立选择对应
`m{AMU}_raw` 的闭区间；`--estimator` 和最低有限点数分别应用到各窗口。默认输出是
`records/vacuum_baseline_review.json` 与输入旁的 `vacuum_baseline_review.png`。指数记录另列锚值、
`k`、`tau=1/k`、残差 MAD/RMSE、窗口斜率及完整范围基线极值；这些是机械证据，不替研究者判断
稳定或接受。审核后再运行：

```bash
tpdtpd vacuum set CONFIG \
  --review-record records/vacuum_baseline_review.json
```

`show` 不生成 `vacuum_baseline.csv`，也不写 TOML；只有人工检查后显式运行 `set` 才保存模型。
常数位于 `[vacuum_baseline.currents_a]`，指数位于
`[vacuum_baseline.exponential."<AMU>"]` 并保存时间坐标、参考点、衰减率、raw SHA-256、来源范围与
review-record 路径/SHA-256。新模型移除同 AMU 旧模型，未点名 AMU 保持不变。共享窗口直接替换
整张映射的旧入口已经删除。

### 4.3 典型交接列

输入可以是 raw 的 `m28_raw`，也可以是当前活动质量信号列。输出会保留本步输入证据并生成当前信号，例如：

```text
m28_input_a   # 本步实际读入的电流
m28_baseline_a # 本行实际扣除的常数或指数基线
m28_signal_a   # 扣除真空电流后的当前活动电流
```

后续 `fragmentation correct` 消费的是 `m{AMU}_signal_a`。指数模型只接受其 SHA-256 绑定的 exact raw，
或 ProcessingRecord 证明直接同源的 `temperature.align` 脱附子表；输入必须有有限、单调的
`acquisition_time_min`，且不得超出被审核 raw 的完整时间范围。vacuum fingerprint 编码实际应用
AMU 的模型类型、系数、时间坐标和来源 SHA-256；模型变化会让旧校准和全部下游谱系失配。

## 5. `fragmentation.*`：从混合质量信号解出物种响应

### 5.1 数学模型

多个物种可能共同贡献同一个质量通道。fragmentation 使用显式矩阵求解：

```text
observed(t) = M @ species(t)
species(t)  = solve(M, observed(t))
```

其中：

- `observed(t)` 是 vacuum 校正后的逐 AMU 电流向量。
- `M` 的行是观测质量数，列是真实物种。
- `species(t)` 是解混后的物种响应，如 `co_resolved_a`、`ar_resolved_a`。

fragmentation 不是响应标定。它回答“各质量通道中的重叠贡献属于哪个物种”；calibration 才回答“目标物种响应相对于内标应乘什么摩尔响应因子”。

### 5.2 审核重点

- `fragmentation show`：确认矩阵的行、列、物种标签和数值方向。
- `fragmentation set`：写入研究者明确提供的矩阵。
- `fragmentation correct`：检查输入通道、求解矩阵和条件数后产生 resolved species 列。

矩阵奇异或条件数超过上限时会失败。`missing_observed=available` 的部分主子矩阵求解意味着同时跳过对应观测行和物种列，并把被跳过物种对保留观测的贡献视为零；只有在有明确实验依据时才应使用，不能把它当作普通缺列补救。

raw/full 与 aligned 都必须先经过 `vacuum subtract` 再进入 `fragmentation correct`。两条支路使用同一当前真空设置和碎片矩阵，后续定量会核对这些指纹是否与校准一致。

## 6. `calibration.*`：用完整采集拟合目标/内标响应因子

### 6.1 为什么放在 raw/full 支路末端

校准必须读取完整采集中的两个互不重叠区间：

1. `calibration background`：通入目标组分前的目标物种背景。
2. `adsorption plateau`：通入已知目标/内标混合气后的稳定平台。

只保留升温段的 aligned 数据通常不包含完整配气切换历史，无法重建这两个区间，因此 `calibration` 严格拒绝 aligned 角色。

### 6.2 计算关系

设：

- \(B_T\)：目标物种在 background 区间的估计值；
- \(T_P\)：目标物种在 plateau 区间的估计值；
- \(R_P\)：内标在 plateau 区间的估计值；
- \(q_\mathrm{expected}\)：本次实际混气的目标/内标摩尔比。

则：

```text
target_plateau_corrected = estimator(T_plateau - B_T)
reference_plateau        = estimator(R_plateau)
measured_response_ratio  = target_plateau_corrected / reference_plateau
response_correction_factor
                         = q_expected / measured_response_ratio
```

这个因子属于目标物种相对于内标的响应校正，不属于某个原始 AMU，也不应重复放进 fragmentation 矩阵。

### 6.3 suggest、preview、compare 与 fit

- `calibration suggest`：自动寻找可能的低背景段和稳定高平台，只产生 provisional 建议。
- `calibration preview`：用研究者明确选择的区间计算指标和图，但不写入最终 reviewed calibration。
- `calibration preview --compare`：在本次 preview 完成后，并列显示 suggestion、本次 preview、可选旧 preview 和当前 active reviewed calibration。
- `--compare-preview-record PATH`：仅与 `--compare` 一起使用，可重复指定多个旧 preview。
- `calibration fit`：研究者复核后正式保存 `[calibration.<species>]`，同时记录输入、处理、vacuum 和 fragmentation 指纹。

比较是 `calibration preview --compare` 的审阅输出，不会把旧 preview 自动提升为
active calibration。

### 6.4 人工复核清单

- background 必须早于 plateau，且两者不能重叠。
- 两段都要有足够有限点数。
- 目标平台扣背景后必须为正，内标平台也必须为正。
- 检查目标和内标平台的 CV，而不只看最终 factor。
- `q_expected` 必须来自本次实际配气组成，不能照搬另一实验。
- preview 图、数值和输入 SHA-256 都确认后，再运行 final `fit`。

## 7. `response_zeroing.*`：aligned 物种响应的可选零点修正

### 7.1 它修正什么

fragmentation 已生成目标物种列以后，研究者可以在明确选择的坐标 \(x\) 上，
从稳定且无峰的窗口 \([x_0,x_1]\) 估计目标物种的常数零点：

```text
b = median(S_target(x)) 或 mean(S_target(x)),  x ∈ [x0, x1]
S_target,zeroed(t) = S_target(t) - b
```

坐标必须显式选为 `program_time_min`、`acquisition_time_min` 或 `temperature_fit_c`。
窗口可以在升温前，也可以在所有峰结束后的尾段；关键是它对当前样品和当前物种
确实稳定、无峰并且代表要归零的响应。命令不会自动猜测“最稳定”的区域。

对某一个 estimate 的局部数学作用是：

- 只修改目标 `{target}_resolved_a`。
- 保存 `{target}_zeroing_input_a`，便于看到修正前数据。
- 其他所有 `*_resolved_a` 物种列逐值原样保留。
- 不修改 calibration 因子、真空电流或 fragmentation 矩阵。

### 7.2 estimate 与 apply 必须分开

- `response_zeroing estimate`：把 target、坐标列、窗口、estimator、最低点数、offset、
  输入哈希和父指纹写入当前 experiment TOML 的 `[response_zeroing.<species>]`，状态为
  pending，不会自动应用。默认另写 `records/<target>_response_zeroing_estimate.json` 和
  `<target>_response_zeroing_estimate.png`。
- 默认 PNG 是四面板审核图：归零前完整曲线、归零前所选窗口、归零后完整曲线、
  归零后所选窗口。研究者必须根据完整信号确认窗口稳定、无峰，并核对归零后该窗口
  是否回到 0 附近。
- `response_zeroing apply`：不接受 target 参数；这一显式动作同时表示接受并应用全部
  匹配的 pending 状态。它从 TOML 保存的精确参数和原输入重算并验证 offset，只处理
  exact fragmentation 输入、父链和 SHA-256 仍匹配的状态，一次生成独立
  `response_zeroed.csv` 分支。没有匹配 estimate 的物种原样通过。

它不是跨实验可复用的仪器常数，但会作为本实验当前输入的计算状态写入现有 experiment TOML。每个 aligned 数据工件都要独立估计和审核；estimate JSON 只作记录/展示，不参与 apply 计算。

### 7.3 对定量和峰面积的影响

`quantify relative` 的第一步是：

```text
target_relative_to_reference(t)
    = S_target(t) / S_reference(t)
```

所以把目标信号改成 `S_target(t) - b` 必然会改变 `quantify relative`，进而可能改变 composition、flow、rate、归一化曲线和峰面积。

如果后续积分基线恰好能完全吸收这个常数偏移，某些理想情况下的面积可能数值不变；但 piecewise-linear 基线、不同锚点、区间边界、内标随时间变化、负值裁剪等都会破坏这种抵消。程序因此不会宣称 `response_zeroing` 对峰面积无影响，而会在 estimate/apply 结果中明确警告其下游影响。

## 8. `quantify.*`：逐点定量，不是峰面积计算

`quantify relative/composition/flow/rate` 都作用于每一个时间点的 resolved species response。它们产生的是曲线，不是峰面积；所以它们必须位于峰识别、积分基线和积分之前。

### 8.1 `quantify relative`

```text
r_response(t) = S_target(t) / S_reference(t)
```

程序使用 calibration 保存的 reference plateau level 建立最低允许内标阈值。内标非有限、为负或低于阈值时会拒绝定量，避免用接近零的分母制造巨大假峰。

### 8.2 `quantify composition`

```text
r_molar(t) = r_response(t) × response_correction_factor
```

此处使用 final reviewed calibration 的乘法因子。`relative` 只是响应比，`composition` 才是校正后的目标/内标摩尔比。

### 8.3 `quantify flow`

```text
Q_target(t) = r_molar(t) × Q_reference
```

`Q_reference` 来自当前已接受的 reference gas 配置。未审核或已因配置变化而 stale 的 reference 会阻止绝对流量换算。

### 8.4 `quantify rate`

把目标 sccm 按配置的标态压力和温度换算为 `response_umol_min`：

```text
n_dot_target(t) = Q_target(t) × P_standard / (R × T_standard)
```

实现同时处理 mL、mol 与 µmol 的单位比例。当前 CLI 要求四步分别运行，每步各写一张 multi-target
long CSV；不再提供 `quantify all` 或 combined 宽表路线。

### 8.5 定量 provenance 门禁

aligned fragmentation 或 response-zeroed 工件必须同时满足：

- artifact role 是 `heating_desorption_aligned`；
- 输入/输出字节 SHA-256 与记录一致；
- response-zeroed 工件的 exact parent 是可验证的 aligned `fragmentation.correct`；
- 目标物种与 calibration 物种一致；
- vacuum 与 fragmentation 指纹和 raw/full 支路拟合 calibration 时一致；
- 当前 TOML 中的 vacuum、fragmentation 和 calibration 没有在处理后发生变化。

文件名或表头不能替代这些条件。

## 9. `normalize`：在逐点摩尔速率之后做样品归一化

`normalize` 通常消费包含 `response_umol_min` 的 quantify 输出，保留绝对速率，同时按配置或人工复核后的样品量生成：

- 按质量的 `response_mmol_min_g`；
- 按质量的 `response_umol_min_g`；
- 如果有 BET，比表面积归一化的 `response_umol_min_m2`。

如果 CLI 显式给出的质量/BET 与 TOML 不一致，必须使用 `--reviewed-sample-override` 承认并记录这次人工覆盖。归一化只改变响应口径，不负责选峰、画积分基线或计算面积。

## 10. `integration baseline`：峰面积积分基线

这是为了定义“面积相对于哪条线计算”的分析基线，和质谱真空电流、response zeroing、calibration background 都不同。

### 10.1 可选形式

- `zero`：基线恒为 0。
- `constant`：由一个明确值或审核区间的 mean/median 得到常数。
- `linear`：连接左右端值或左右审核区间得到的一条直线。
- `piecewise-linear`：使用多个锚点区间；每个锚点从该温区估计响应水平并定位到其中位程序时间，再在相邻锚点间线性连接，适合多峰或缓慢漂移背景。

若当前样品的 response zeroing 已审核且无峰区确实回到 0 附近，应优先审核
`zero` integration baseline。如果仍有小的常数偏移，可对当前样品审核一个靠近 0 的
`constant` baseline。同一样品、同一 target 的两个峰应共享这一个数值，而不是为
每个峰各自找点连线。只有当完整曲线显示实际漂移需要建模时，才应选择 linear 或
piecewise-linear，并单独审核。

### 10.2 preview → 人工审核 → accept

`integration baseline preview` 生成：

- experiment TOML 中 pending `[integration_baseline.<species>]` 可复算定义；
- 默认 `records/<target>_integration_baseline_review.json`；
- 同时显示原响应、候选基线和扣基线响应的预览图；
- config/input SHA-256、模式、锚点、估计值和解析后的范围。

研究者检查基线是否穿过真实无峰区域、是否错误吞掉宽峰/肩峰，以及多峰间谷底是否适合作为锚点。
确认后运行 `integration baseline accept`；CLI 重新核对 normalized 输入、target 与定义指纹，把状态改为
reviewed，并写 `records/<target>_integration_baseline_acceptance.json`。preview/accept 都不生成
baseline-subtracted CSV；后续命令从 `normalized.csv` 与 reviewed baseline 直接复算。

同一样品、同一 target 的多个峰共享已审核 baseline 时，应在一次 `integration areas`
调用中使用一个稳定 `result-id` 和多个具名区间。如果真的需要不同科学分支，应使用
独立 config 分支分别执行 `preview → 人工审核 → accept → areas`，避免后一次
preview 替换前一分支入口。不得把审核范围外的 endpoint-held extension 当作另一峰
已经审核的基线，也不得把一个样品的 offset 或 baseline 复用给另一个样品。

## 11. `integration peaks` 与 `integration areas` 不应合并

### 11.1 `integration peaks`

它只做候选峰识别：

- 在研究者指定温区内工作；
- 使用局部二次平滑降低噪声；
- 按正峰或负峰方向寻找局部极值；
- 应用最小峰高、最小峰间距和峰数规则；
- 可根据峰间谷底给出候选区间。

这些峰和谷底的状态是 `unreviewed candidate`，不会自动成为正式积分边界。命令从 multi-target
`normalized.csv` 选择 `--target`，应用 TOML 中 reviewed baseline，再把候选摘要写入
`[integration_peaks.<result-id>]`，逐点证据写入 `records/<result-id>_peaks.json`。它不生成峰表或曲线 CSV。

### 11.2 `integration areas`

它不找峰、不拟合另一条基线，只从同一 `normalized.csv` 与 reviewed baseline 复算；JSON 不参与科学
状态选择。研究者必须明确输入一个或多个命名温区。

虽然区间用温度给出，数值积分使用每个采样点真实的 `program_time_min`：

```text
area = trapezoid(baseline_subtracted_response, actual_program_time)
```

这样得到的面积单位才是数量单位，例如 `(µmol/min) × min = µmol`。命令还要求明确决定：

- 是否在区间边界插值；
- 是否把负值裁剪为 0；
- 是否只 preview，还是正式写入 TOML 面积；
- 是否允许使用基线审核区间之外的端点保持外推。

因此 `integration peaks` 的作用是辅助研究者选区间，`integration areas` 的作用是对已审核区间执行
正式积分。两者不能自动串联。

正式积分会按稳定的 `--result-id` 新增或替换一项 `[peak_integration.<result-id>]`，每个命名区间保存：

- 请求/实际积分温区；
- 峰位置、该位置的积分响应和位置语义；
- `amount_umol`、`amount_umol_g`、`amount_mmol_g`，以及实测 BET 存在时的 `amount_umol_m2`；
- 本次质量和 BET 快照；
- normalized 输入 SHA-256 与 baseline 定义指纹。

没有显式 `--peak-position INTERVAL TEMP_C` 时，峰位置只是区间内积分响应最大采样点，语义为
`maximum-integration-response-sample`，图中标 `Tmax`；科研人员显式给出的已复核位置才是
`reviewed-explicit`，图中标 `Tp`。`--preview` 默认写 `records/<result-id>_areas_review.json` 与审核图，
不写正式 TOML；正式调用写 `[peak_integration.<result-id>]` 和 `records/<result-id>_areas.json`，两种模式
都不生成 integration summary/curve CSV。

### 11.3 单样完整温程图与跨样比较图

`plot response` 默认使用 `--display-range program`：从 `program_time_min >= 0` 开始，到第一次最高温
结束，因而显示完整升温支路，而不是积分峰区。只有 `analysis` 才看审核区，只有 `custom` 才接受成对的
`--start-c/--end-c`。默认从同一目标物种的正式 `[peak_integration.*]` 读取标注，并在绘图前重新核验
normalized 输入 SHA-256 与 baseline 指纹；图上的面积单位始终和所选 basis 一致。

`plot comparison` 要求至少两组显式 `LABEL CONFIG INPUT`，默认生成共享温度轴的三行图：

1. 绝对响应 `µmol min⁻¹`；
2. 质量归一化响应 `µmol min⁻¹ g⁻¹`；
3. BET 归一化响应 `µmol min⁻¹ m⁻²`。

横轴是各实验完整升温支路的并集，但每条曲线只画自身实测范围，不做外推；各 panel 内样品使用同一
纵轴尺度，负值保留并画零线。图底表格逐峰列出位置语义、温度和三种面积。完整曲线来自各自 total
normalized CSV，逐峰面积来自各样品自己已审核的 baseline；同一样品的多个峰可共享该基线，
不同样品不共享数值。完整曲线与面积的口径会在标题中明确。默认三 panel 时任一样品
缺真实质量、BET、响应列或对应正式面积都会整体失败，绝不拿 0、另一个样品的 BET 或临时推算值补齐。

## 12. 推荐的操作与审核顺序

下面是科学顺序，不是要求一次自动执行的流水线。每一步都应检查 stdout/stderr、输出文件、图和记录，再决定是否继续。
真实运行优先使用 CLI 已定义的默认 basename；只需要换输出目录时，仅改父目录并保留
basename。不擅自加 `fresh`、`final`、`v2`、日期或时间戳。必填的 `--result-id` 是 TOML 中的
科学身份，不是临时文件名装饰；应使用已审核的稳定 ID 或最小职责型 ID。

### 12.1 准备共同配置

1. `config inspect` 检查 schema 4、原始 RGA、温度日志和配置；需要特定通道时重复指定 `--require-mass`。
2. `reference show → set（如需）→ show → accept`。
3. `vacuum show --input ... --baseline-model constant|exponential --signal-window ...（每 AMU 独立）
   → 人工检查 JSON/图片 → vacuum set --current 或 --review-record`。
4. `fragmentation show`；有实验依据时才 `fragmentation set`。

### 12.2 raw/full 校准支路

```text
tpdtpd vacuum subtract CONFIG --input RAW.csv
# 默认在输入旁写 calibration_vacuum.csv
tpdtpd fragmentation correct CONFIG --input calibration_vacuum.csv
# 默认在输入旁写 calibration_fragmentation.csv
tpdtpd calibration suggest CONFIG --input calibration_fragmentation.csv ...
tpdtpd calibration preview CONFIG --input calibration_fragmentation.csv ... --compare
# provisional 状态进 TOML，详细证据进 records/；不写 CSV
tpdtpd calibration fit CONFIG --input calibration_fragmentation.csv ...
# reviewed calibration 进 TOML，详细证据进 records/；不写 CSV
```

其中 `...` 表示必须由本次实验明确提供的目标/内标、实际配气比、背景区间和平台区间；
输出路径已有职责型默认值，不属于必须手填的科学参数。不要把示意文本直接当成完整命令。
用 `tpdtpd calibration <action> --help` 查看当前精确参数。

### 12.3 aligned 定量支路

```text
tpdtpd temperature align CONFIG
# 默认读取 canonical temperature_model.tpxmodel，并写 aligned.csv
tpdtpd vacuum subtract CONFIG --input aligned.csv
# 默认写 desorption_vacuum.csv
tpdtpd fragmentation correct CONFIG --input desorption_vacuum.csv
# 默认写 desorption_fragmentation.csv
```

两条支路使用不同职责型默认名，可以在同一目录中同时保留；文件名不累计处理历史。

然后选择一条：

```text
# A：不做响应归零
tpdtpd quantify relative CONFIG --input desorption_fragmentation.csv --target CO ...

# B：建立可审核的响应归零分支
tpdtpd response_zeroing estimate CONFIG \
  --input desorption_fragmentation.csv \
  --target CO \
  --coordinate-column program_time_min \
  --zero-window=-5:0
# estimator=median、minimum-points=3 均已有默认值
# 默认 JSON 写入 records/，默认四面板 PNG 写在输入旁

# 其他物种必须用各自审核的 target 和区间分别 estimate，不能复用 CO 的选择
# 人工分别检查四面板图后；apply 表示接受并应用全部匹配 pending 状态
tpdtpd response_zeroing apply CONFIG \
  --input desorption_fragmentation.csv
# 默认写 response_zeroed.csv

tpdtpd quantify relative CONFIG --input response_zeroed.csv ...
```

随后依次执行 `quantify composition`、`quantify flow`、`quantify rate`；四步默认写
`relative.csv → composition.csv → flow.csv → rate.csv`。多个 target 可用 `--target CO,NH3` 共用同一组
long CSV。再执行 `normalize --input rate.csv`，默认写 `normalized.csv`。

对当前样品完成后半段。同一 target 的两个峰共享 reviewed baseline 时，使用一次
`integration areas`、一个稳定 `result-id` 和多个具名区间，例如：

```text
tpdtpd normalize CONFIG --input rate.csv

tpdtpd integration baseline preview CONFIG --input normalized.csv --target CO ...
# 人工审核；随后 accept 同一输入和定义
tpdtpd integration baseline accept CONFIG --input normalized.csv --target CO

tpdtpd integration peaks CONFIG \
  --input normalized.csv --target CO --result-id co_candidates ...

tpdtpd integration areas CONFIG \
  --input normalized.csv --target CO --result-id co_integration \
  --start-c REVIEWED_START_C --end-c REVIEWED_END_C \
  --interval-name peak-1 \
  --interval peak-2 PEAK2_START_C PEAK2_END_C
```

其中 `...` 和 `REVIEWED_*` / `PEAK2_*` 必须来自当前曲线的人工审核，不是本 SOP 的
默认参数。不同样品必须在各自的 experiment TOML 中独立审核 response-zero offset 和
integration baseline，不共享数值。所有峰正式写入后，单样和比较图可分别运行：

```text
tpdtpd plot response CONFIG --input normalized.csv --target CO \
  --response-mode total --basis mass-umol

tpdtpd plot comparison \
  --series SAMPLE_A CONFIG_A NORMALIZED_A.csv \
  --series SAMPLE_B CONFIG_B NORMALIZED_B.csv \
  --output response_comparison.png
```

## 13. 关键工件及其意义

| 工件 | 典型内容 | 状态/用途 |
|---|---|---|
| `records/vacuum_baseline_review.json` / `vacuum_baseline_review.png` | 输入哈希、逐 AMU 模型/窗口/点数/锚值和机械诊断；完整信号与模型，指数图另含扣后信号和零线 | `vacuum show` 的 pending 审核材料；默认 JSON 在 `records/`、图片在输入旁，TOML 不变 |
| `calibration_vacuum.csv` / `desorption_vacuum.csv` | `m*_input_a`、逐行 `m*_baseline_a`、`m*_signal_a` | 两条支路已扣逐 AMU 常数/指数真空模型；角色未知时回退 `vacuum.csv` |
| `calibration_fragmentation.csv` / `desorption_fragmentation.csv` | `*_resolved_a` | 两条支路已解混物种响应；角色未知时回退 `fragmentation.csv` |
| `[calibration_preview.<species>]` / `[calibration.<species>]` | factor、平台、CV、区间、处理指纹 | provisional preview / reviewed fit；详细证据在 `records/`，无 CSV |
| `[response_zeroing.<species>]` | target、coordinate/window、estimator、minimum_points、offset、输入哈希与父指纹 | estimate 写入的 pending 计算状态；apply 从原输入重算并验证 |
| `records/<target>_response_zeroing_estimate.json` / `<target>_response_zeroing_estimate.png` | 窗口、估计器、点数与 offset；归零前/后完整曲线及所选窗口 | estimate 的记录 JSON 与默认四面板审核图；JSON 不参与 apply 计算 |
| `response_zeroed.csv` | 所有匹配目标各自的归零前/后列及未配置物种列 | 无 target 参数的 apply 生成的可选正式 aligned 定量分支 |
| `relative.csv` / `composition.csv` / `flow.csv` / `rate.csv` | 响应比、摩尔比、流量或速率 | multi-target long 逐点定量曲线；`target_species` 区分物种 |
| `normalized.csv` | 绝对、质量、BET 响应 | 最后一张可复用逐点科学数据表 |
| `[integration_baseline.<species>]` | 基线定义、输入哈希、参数与 review 状态 | preview 写 pending，accept 改为 reviewed |
| `records/<target>_integration_baseline_*.json` | 基线 review/accept 详细证据 | 不生成扣基线 CSV |
| `[integration_peaks.<result-id>]` | 候选峰摘要与输入/基线指纹 | unreviewed candidates；详细证据在 `<result-id>_peaks.json` |
| `[peak_integration.<result-id>]` | 峰位语义、逐区面积、样品属性快照和输入/基线指纹 | 正式、可核验、可供绘图的逐峰结果；按 ID 独立替换 |
| `records/<result-id>_areas*.json` | preview 或正式逐点积分证据 | 不生成 summary/curve CSV |
| `<target>_response_<mode>_<basis>_<range>.png` | 单样完整/审核/custom 曲线及正式峰注释 | 目标、口径、basis、温区进入默认名，避免多物种覆盖 |
| response comparison PNG/PDF | 多样完整曲线、三种纵轴、逐峰标记和面积表 | 显式输出路径；默认缺 BET 时整体失败 |

## 14. ProcessingRecord 为什么重要

成功的数据处理命令会为实际输出工件把 ProcessingRecord 追加到实验 TOML。记录只用于绑定该工件身份与谱系：

- stage；
- artifact role；
- 输入/输出绝对路径和 SHA-256；
- 参数指纹；
- 父处理指纹；
- vacuum、fragmentation、alignment 等科学设置指纹；
- 适用时的目标物种。

这些记录防止以下错误：

- 把 raw 校准表误当成 aligned 脱附表；
- 用 aligned 数据重新拟合 calibration；
- 在 vacuum 或 fragmentation 配置改变后继续使用旧 calibration；
- 修改 estimate 所绑定的输入后仍尝试 apply；
- 把手工改名的 CSV 当成已审核输出；
- 对不含所需物种或父链不匹配的 response-zeroed 工件执行当前物种定量。

自动检查通过只代表处理链和字节证据自洽，不代表科研人员已经接受曲线、区间、矩阵或模型。preview/show、人工复核和 apply/fit 的边界必须保留。

## 15. 当前命令名称

旧名称不再提供兼容别名：

| 旧名称 | 当前名称 | 变化原因 |
|---|---|---|
| `preheat estimate/subtract` | `response_zeroing estimate/apply` | 明确它位于 species response 域，并保留人工审核后 apply 的分支 |
| `integration_baseline preview/apply` | `integration baseline preview/accept` | 基线成为 TOML review 状态，不再发布扣基线 CSV |
| `detect_peaks` | `integration peaks` | 候选摘要与逐点证据归入统一 integration 命令族 |
| `integrate_peak_areas` | `integration areas` | 正式面积写 TOML/JSON，不再发布 summary/curve CSV |
| `quantify all` | 四个 `quantify` action | 每个科学换算独立、可审核，并支持 multi-target long 表 |

## 16. 最容易犯的错误

1. **在 fragmentation 之前做 response zeroing**：此时仍是混合 AMU 信号，无法保证只修改目标物种。
2. **拿 aligned CSV 做 calibration**：aligned 数据没有完整校准背景与配气平台，且角色门禁会拒绝。
3. **把 calibration background 当作脱附基线**：它只服务于校准 factor 的平台增量。
4. **认为 response zeroing 不影响 relative**：relative 的分子就是目标响应，减常数后必然变化。
5. **先找峰/积分再 quantify**：quantify 是逐点响应换算，峰面积应在定量和归一化之后。
6. **让 integration peaks 自动决定正式积分边界**：检测结果只是候选，必须人工复核并显式输入积分区间。
7. **只看文件名判断数据阶段**：当前 CLI 使用 SHA-256、角色和父链，不接受文件名推断。
8. **把命令成功当成科学接受**：数值可计算不表示区间、矩阵、零点或峰归属已经被研究者接受。
9. **把文件名当作 target 或 provenance**：multi-target long 表依靠 `target_species` 和 ProcessingRecord，
   不是把物种、质量、BET 和处理历史都塞进文件名。
10. **把自动最大点写成正式 `Tp`**：未显式复核时它只能标为 `Tmax`，不能把 integration peaks 候选或截图数值自动升级。
