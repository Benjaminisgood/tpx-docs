先明确：表格有行和列，曲线只有一维轴

curve_from_response_table() 不按列位置猜测含义。它只消费三个点名的数值列，并把单位写进新的只读 Curve。

真实输入 DataFrame · (N, M)

N 行采样点，M 列已处理数据。

  1. 01显式映射Curve · 3 × (N,)
  2. 02独立积分IntegrationResult
  3. 03独立找峰PeakResult

默认读取的三列

响应列和响应单位仍由调用者显式给出。

DataFrame 列单位Curve 字段
program_time_minminx · (N,)
response_umol_minµmol min−1y · (N,)
temperature_fit_c°Ccoordinates["temperature"] · (N,)

DataFrame 的 index 和其他列不会进入这个 Curve；需要它们时应在原表中单独保留和复核。

进入 Curve 前的硬约束

每条轴都必须代表同一批采样点。

检查真实约束
维度三个数组都必须是一维
长度长度相等，且 N ≥ 2
数值全部有限；缺失值不会填成 0
积分时间x 必须严格递增
单位不靠猜

SDK 固定把默认时间列标为 min、温度辅助轴标为 degC，但响应单位来自 response_unit。如果换响应列，必须同时传入与数值一致的响应单位。

这一步实际调用什么？

pandas.read_csv → curve_from_response_table → Curve.from_frame → Curve

构造函数复制三条数值数组、检查形状和有限性，再设为只读；它不改写原 DataFrame。

01

运行一个只读、逐项询问的脚本

在项目环境中先确认公共包可导入，再把下面脚本保存为 sdk_quickstart.py。温区、峰间距、平滑与阈值由交互输入；其余策略在代码中显式写出，运行前仍须逐项复核或修改。

脚本会写文件或修改配置吗？

不会。它只读取一张 CSV、在内存中创建对象并打印结果。要保存表格时，应从点名的 Curve 明确导出，例如 integration.corrected.to_frame().to_csv(NEW_PATH, index=False)，并选择新的输出路径。

运行前先确认

  • 输入已经完成你接受的校准和定量步骤。
  • 三列来自同一实验、同一行坐标。
  • 分析温区与基线温区来自原曲线人工复核。
  • 峰间距、平滑和阈值适合当前采样密度与噪声。

脚本不自动推断科学参数。交互项必须输入；代码中写明的 constant / positive / keep-negative / interpolate / count=None 也只是示例选择，不能当作当前样品的通用默认。

解释 IntegrationResult：温度选区，时间积分

Interval(axis="temperature") 决定保留哪些采样点；梯形积分仍沿主轴 program_time_min 进行。

闭区间选点 temperature · degC

默认在线性插值后精确落到人工给出的两个温度边界。

→
梯形积分 x · min

µmol min−1 × min 自动推导为 µmol。

字段类型或形状含义
value / unitfloat / str扣分析基线后的积分量与推导单位
regionCurve · (K,)温区内曲线；边界插值最多增加两个点
baselineBaselineResult本次分析基线、扣除曲线和左右水平
correctedCurve · (K,)扣基线后、保留负值的积分信号
cumulativeCurve · (K,)逐点累计积分，便于复核面积来源
specIntegrationSpec原样保留这次参数
两种 baseline

脚本里的 constant + median 是研究者为当前响应曲线选择的分析基线。它不是仪器的 vacuum baseline，也不是把缺测通道补成 0 A。本例保留扣基线后的负值；改为截零会改变积分量。

积分实际经过哪些对象？

Curve + IntegrationSpec → integrate_curve → BaselineResult + corrected Curve + cumulative Curve → IntegrationResult

积分器不调用 detect_peaks。即使没有候选峰，人工温区仍可独立积分。

研究者必须判断

  • 分析温区是否只覆盖要归属的事件。
  • 基线温区是否无峰且具有代表性。
  • constant median 是否符合曲线背景形态。
  • 是否保留负值和是否插值边界。

当前只实现 trapezoid；传入其他 method 会明确报参数错误。

解释 PeakResult：候选位置不是机理归属

detect_peaks() 使用自己的温区、极性、间距、平滑和阈值。它返回局部极大值候选，不计算面积。

字段类型或单位怎样理解
peakstuple[Peak, ...]P 个候选，最终按温度位置排序
smoothedCurve · (Kp,)只用于复核峰识别，不回写积分输入
smoothing_half_window_points点数由输入的 °C 全宽和实际温度间距换算
Peak.index局部索引温区截取后曲线中的位置，不是原 DataFrame index
Peak.xmin候选处的程序时间
Peak.position°C候选峰温
Peak.heightµmol min−1平滑曲线上的候选峰高
  1. 01截取

    按温度闭区间选择原曲线。

  2. 02平滑

    0 表示不平滑；非零窗口按实际温度步长换算。

  3. 03筛选

    应用正峰、最小峰高与最小峰间距。

  4. 04返回

    count=None 保留满足条件的候选集合。

count=None 与 strict=False 代表什么？

脚本不预先规定峰数，也不会因为返回 0 个候选而报错。这适合先检查，但不表示所有局部极大值都是真实脱附峰。

Curve + PeakSpec → detect_peaks → local_quadratic_smooth → PeakResult

研究者必须判断

  • 正峰或负峰是否符合信号方向。
  • 平滑是否保留窄峰又抑制噪声。
  • 峰间距与阈值是否有实验依据。
  • 候选是否在重复实验中稳定出现。
  • 任何物种、位点与机理归属是否有独立证据。

峰温来自平滑候选点；不要从打印结果直接跳到机理结论。

运行结束后，逐项核对

  • 01输入形状

    (N, M) 与三条 (N,) 是否符合预期。

  • 02坐标单位

    时间是 min、温度是 °C、响应是 µmol min−1。

  • 03积分区域

    region 的 K 个点是否对应人工温区。

  • 04基线曲线

    constant level 与 corrected 曲线是否合理。

  • 05平滑曲线

    候选峰是否来自可接受的平滑结果。

  • 06参数来源

    保存本次输入，而不是只保存最终数字。

常见错误怎么定位

UsageError 通常表示参数组合不成立，DataError 通常表示数据或范围不满足计算；文本转数值失败也可能直接是 ValueError。

Response table is missing column(s): ...

输入缺少时间、拟合温度或点名响应列。回到产生该表的上一步检查，不要复制别的列或用 0 补齐。

Curve ... contains non-finite values.

三列中存在 NaN 或无穷值。先定位缺测来源并保留科研缺失语义；SDK 不会静默填零。

Integration x values must be strictly increasing.

程序时间倒退或重复。先核对排序、时钟和对齐过程，而不是只对响应列排序。

温度边界无法精确插值

两个边界必须位于实测温度范围内，温度辅助轴还要非递减。多循环或降温数据需要先人工选择合适段。

constant baseline 参数被拒绝

constant 必须恰好提供一个显式值或一个采样区间；使用区间时还要选择 median 或 mean。

非零平滑窗口被拒绝

换算后半窗口必须至少 2 点，整条选区也必须容纳它。检查采样间距，再决定用 0 或更有依据的 °C 窗口。

想把积分结果单位改成别的标签

result_unit 不会替你做数值换算，也不能静默把 µmol 重标成 mmol。先完成明确的数值换算，再使用一致单位。
