# TPX nanobot 实验助手

TPX 的聊天入口由独立的 `tpxtpxtpx` nanobot 运行时与 WebUI 提供。科学处理使用同仓库的
`tpx` SDK、`tpxtpx` CLI 和内置工作流插件。实验步骤通过可编辑聊天卡片或「应用 → 实验处理」
页面交互；研究者逐步检查参数、执行结果和科学假设，再决定下一步。

## 启动与实例

按[项目总览](../README.md)准备 Docker 与 Python，然后从仓库运行
`启动TPX.command` 或 `启动TPX.bat`。默认 WebUI 为 `http://127.0.0.1:8766`，
健康检查端口为 18791。默认后台 Docker 在启动后允许关闭终端；`--local` 使用本机后台进程，
`--foreground` 用于前台调试。实例配置、凭据与会话位于 `~/.tpxtpxtpx`，也可通过启动器
`--home` / `--workspace` 明确选择另一实例和实验工作区。

模型和 Provider 在网页设置中配置。没有 Provider 时，确定性的科学应用仍可使用；模型聊天
需要有效的模型连接。TPX 不加载相邻 TAP/TAK 的配置、凭据或代码。

## 本机与 OSS 文件

「设置 → 存储」配置阿里云 OSS，「应用 → 文件」浏览本机与 `oss://` 路径。
远端目录先完整导入新的本机工作副本，再带入实验处理；保留源字节、目录和哈希清单，不自动改写 TOML。
默认只读；显式允许上传后仍使用新对象路径，不覆盖已有结果。详见[存储说明](storage.md)。

## 从当前命令目录准备步骤

1. 在「应用 → 实验处理」选择服务器上的实验目录与 `experiment.toml`。新建配置时明确输入文件，
   已有配置不得被 init 隐式覆盖。
2. 从当前安装返回的 catalog 选择命令。参数表单来自真实 parser，填写文件、物种、单位、
   窗口和其他科学决定；不要从文件名或 m/z 猜测物种和实验条件。
3. 点击检查/准备，查看将执行的完整 argv、输入身份、配置哈希及读写影响。准备操作不执行科学计算。
4. 审阅后点击运行；写入和科学接受类步骤需要明确确认。执行前重新核对配置、输入、参数和运行时，
   变化会使旧计划失效。一次计划只能执行一次。
5. 查看状态、完整 stdout/stderr、结果表和图。需要中止时使用取消；失败或取消也保留运行事实，
   不能把失败时的空结果当作有效科学输出。

浏览器可以把步骤带入当前或新聊天。Agent 的 `tpx_workflow` 工具先读 `catalog` / `describe`，
再检查和准备 `tpxform` 卡片；它可以解释结果、提出下一步参数，但不能通过工具调用自行启动科学运行。
卡片仍由研究者编辑和执行。没有网页的通道可提供准确 CLI 与待审阅参数，保留相同的逐步决定边界。

## 文件与记录

| 内容 | 位置与职责 |
|---|---|
| 实验事实、配置、审核状态 | 外部可编辑 `experiment.toml`；不会改成隐藏数据库配置 |
| 原始输入、模型、CSV、图和科学 JSON | 明确的实验目录；保留全量源点和既有结果 |
| ProcessingRecord | experiment TOML 中的输出工件身份、来源哈希与父链 |
| 工作流计划与进程记录 | 实例配置旁的 `tpx-workflow/plans/` 与 `runs/` |
| 聊天与模型配置 | 当前 nanobot 实例的配置、工作区与会话目录 |

`runs/` 中的 `receipt.json` 与日志记录命令、计划、输入、用户确认、退出状态及工件；它们不是
ProcessingRecord，也不是人工科学接受记录。目录中发现的旧文件与本次运行输出分开呈现。
工件预览和下载核对列出时的 SHA-256；引用某次运行时还需与该运行记录一致。CSV 按完整行读取，
科学处理与绘图不做抽稀。

## 科学决定仍需逐步审阅

温度建议不等于接受温程模型；真空扣除、碎片求解、响应归零、定量与积分基线是不同运算。
标气完整采集支路和升温脱附支路保留各自来源链。物种、质量、BET、流量、参考气标准状态、
标定因子、基线窗口和峰区间必须来自本实验的证据。

工具成功、退出码 0、哈希一致、图形可见或拟合优度好都只是技术证据，不能替代对边界、模型、
单位和机理解释的科学接受。`preview/show/suggest`、`set/accept` 与真正写入信号工件的操作
不能互相替代。具体步骤见[科研流程](scientific-workflow.md)、[CLI 参考](cli-command-reference.md)
和[控制协议](control-protocol.md)。

## 项目应用与扩展

`tpxtpxtpx/apps/workflow/` 提供实验处理服务和专用技能；`tpxtpxtpx/apps/calculate_ea/`
提供 leading-edge 表观脱附能应用、CLI 和技能。Ea 保留全部源点和重复温度点，并要求明确温度单位、
时间或升温速率来源及适用假设；计算成功不能证明所选窗口符合模型。

当前默认启用 `workflow`、`calculate-ea`，由实例配置 `tpxApps.enabled` 控制。
禁用插件后，其工具、技能和路由不再提供。科学脚本置于 `labcode/`，未来实验室程序放入 `labview/`；
只有经过适配和验证的程序才作为可执行能力接入，不把预留目录写成已完成硬件控制。

当前 TPD 已包含温程、真空、碎片、标定、四步定量、归一化、基线、面积、峰温和绘图；
TPR/TPO 保留占位入口，不声称已实现相应算法。源码来源和选择性升级边界见[迁移说明](nanobot-migration.md)。
