# 本机与阿里云 OSS 存储

在「设置 → 存储」配置 OSS，再在「应用 → 文件」访问本机目录或 `oss://bucket/prefix/`。
OSS 接入使用官方 `oss2` SDK，Docker 已包含依赖；本机安装使用 `pip install -e '.[oss]'`。

## 设置与凭证

每个挂载需要唯一 ID、Bucket、地域和 HTTPS Endpoint，例如 `cn-shanghai` 与
`https://oss-cn-shanghai.aliyuncs.com`。可用前缀限制可访问的对象范围，默认为只读。
同一 Bucket 的相同前缀不能重复；嵌套前缀采用最长匹配挂载的权限和凭证。设置保存后文件操作读取最新配置。

AccessKey ID、Secret 和可选 STS Token 写入当前实例的 `auth/oss/`，POSIX 文件权限为 `0600`，
目录为 `0700`。`config.json` 的 `tools.file.oss` 仅保存挂载与凭证引用；浏览器只显示是否配置。
重新编辑时空白凭证字段表示保留，替换时必须同时填写 ID 与 Secret。不要把密钥写入聊天、
实验 TOML、Git 或截图。没有选择凭证引用时，可由运行服务的环境提供 `TPX_OSS_ACCESS_KEY_ID`、
`TPX_OSS_ACCESS_KEY_SECRET`、`TPX_OSS_SECURITY_TOKEN`；已有引用失效时不会偷偷切换账户。

实例通过启动器在本机与 Docker 之间切换时保留相同凭证目录；TAP/TAK 的凭证不被读取。
若阿里云返回 `403 UserDisable`，说明对象请求被云服务以该状态拒绝；界面保留错误信息。
配置保存成功、Bucket 可发现都不能证明对象读取或上传已获允许。

## 科学处理使用完整工作副本

1. 在文件页选择远端目录，导入到一个新的本机目录。
2. 导入遍历全部分页和子目录，按原始字节下载，核对传输大小及 ETag，记录 SHA-256。
   下载中途失败不会留下看似完整的目标目录；已有目标和并发创建的目标都不会被覆盖。
3. 成功后将工作副本带入实验处理。先检查 `experiment.toml` 的相对路径、外部绝对路径、单位、
   物种及输入身份，再准备冻结计划。导入不重写 TOML，也不进行抽稀、平均或数值格式转换。
4. 科学输出保留在工作副本或明确选择的新本机路径。需要归档时由用户选择文件上传到新的 OSS 对象。

导入清单位于实例 `storage/imports/`，记录来源 URI、ETag、大小、SHA-256 与本机位置。
远端目录不是数据库事务快照：单个对象列表中的 ETag/大小与实际下载不一致时导入会失败。
已下载对象之后的变化不会被再次检查，新增对象也不一定进入本次清单。
研究归档需要冻结输入并核对清单。只读挂载禁止上传；允许上传后也默认拒绝覆盖已有对象。
没有自动同步、云端原地编辑或批量删除。

文本和图像可预览。超出预览大小上限时明确提示下载完整文件；预览限制不会改变下载与处理的数据。
本机浏览路径是服务器可见路径：Docker 默认提供工作区与 Desktop，可用启动器 `--mount` 增加目录。
开启工作区限制后，本机访问不能逃离工作区，Agent 的远端文件访问也被限制，需先导入到本机工作区。

## 接口边界

认证后的读取接口是 `/api/tpx/storage/status`、`list`、`preview`。配置、下载、目录导入及上传
通过认证 WebSocket 的 `tpx.storage.call` 执行；不支持用 HTTP GET 触发写入。
Agent `read_file` / `list_dir` 可访问已配置挂载；`write_file` 只能创建新对象，`edit_file` 不提供远端原地编辑。
普通执行工具与科学 CLI 不把 `oss://` 当成本机 POSIX 路径。
