01

先让每只时钟说清自己

墙钟给绝对锚点，累计计时给段内精度；两者职责不同，不能删掉其中一个。

rga_elapsed_hms
HAL 原始 Time 的显示文本；保留用于复核，不拿它做跨仪器计算。
acquisition_time_min
RGA ms 相对首个有效采集行的分钟数；起点是“开始采集”。
clock
温控日志的秒级本地墙钟；跨午夜回退时，读取器把日期推进一天。
elapsed_s
温控计数器；在一个连续锚点段内保留亚秒采样间隔。
program_time_min
相对复核后有效 heat_start 的分钟数；它是派生坐标，不是第三只仪器时钟。

PAUSE REGRESSION FIXTURE

为什么不能只看 elapsed_s？

温控计数器可能在仪器暂停时重复。若只累计它，会把真实的墙钟空档压缩掉；读取器会从新的 clock 锚点重新开段，再继续使用 elapsed_s 的段内精度。

只看 elapsed_s 0 → 1.1 → 1.1 → 2.2 s 9 秒暂停被压缩
clock 新锚点 + elapsed_s 0 → 1.1 → 10 → 11.1 s 保留暂停，报告 1 个 discontinuity
--clock-elapsed-tolerance-s 默认 1

相邻行的 clock 步长与 elapsed_s 步长相差超过默认 1 秒，或 elapsed_s 不再递增时，程序新建锚点段。1 秒是可覆盖的默认分段判据，不是允许两只仪器整体漂移 1 秒，也不是物理常数。

HAL CSV→tpx.io.read_rga_csv()→datetime · temperature TXT→tpx.io.read_temperature_log()→datetime

建议、复核、拟合、对齐：四个边界

命令不会把 suggestion 偷换成结论，也不会自动执行下一步。

  1. 01 · suggest 机器提出候选边界

    读取温控日志，输出候选与警告；成功结果写入 provisional TOML 记录。

  2. 02 · human review 研究者检查物理事件

    确认起止时刻、候选歧义、暂停分段与数据来源。

  3. 03 · fit 显式边界拟合模型

    直接 CLI 必须给出复核后的两个 ISO 本地时间；不再自动寻找升温段。

  4. 04 · align 加载模型并对齐

    只加载明确选择的 .tpxmodel，再按本次 align 的时钟容差、偏移和越界策略把模型应用到 RGA 行；fit CSV 与 fit record 不参与计算。

不要原样复制尖括号。 <REVIEWED_START_ISO> 与 <REVIEWED_END_ISO> 必须替换为本次实验中人工复核的 YYYY-MM-DDTHH:MM:SS[.ffffff]；直接 CLI 调用没有隐藏边界默认值。三个输出路径已有按配置位置解析的默认值，默认或覆盖后的目标都必须尚不存在。

DEFAULT MODEL · ISOTONIC REGRESSION

monotonic：单调非降保序回归温度拟合

当前默认模型不是多项式、PCHIP 或单调三次样条。它先平滑人工确认升温段的 temperature_real，再用相邻违背者合并算法 （Pool-Adjacent-Violators Algorithm，PAVA）求最小二乘非降序列， 最后按时间结点作分段线性重放。

最小二乘目标 min Σᵢ (zᵢ − ỹᵢ)²
非降约束 z₁ ≤ z₂ ≤ ⋯ ≤ zₙ

ỹᵢ 是滚动平滑后的升温段实测温度，zᵢ 是拟合温度。 默认平滑窗口为 31 点、估计量为中位数；也可以显式改用均值。

  1. 01 · smooth 先抑制局部测量噪声

    在复核后的 ramp 内做居中滚动 median 或 mean；边缘保留现有点，不丢掉端点。

  2. 02 · PAVA 合并相邻逆序块

    若前块温度高于后块，就按各块点数加权平均并继续向左检查，直到所有结点非降。

  3. 03 · complete model 平台与 ramp 再整体保序

    前平台、保序 ramp、后平台拼接后再次运行 PAVA，防止接口产生人为冷却步。

  4. 04 · replay 按结点线性重放

    ramp 内用 np.interp 分段线性插值；升温前后分别使用常值平台。

PAVA 的一次合并 100, 103, 102 °C → 100, 102.5, 102.5 °C

因为 103 > 102 违反非降约束，两个等权点合并为 (103 + 102) / 2 = 102.5 °C。若新块仍低于左侧块，就继续向左合并； 因此下降噪声通常会变成一段平台，而不是被解释成真实降温。

它保证什么，又不证明什么

monotonic 保证完整拟合输出不下降，但不是“严格递增”，所以允许平台和折点； ramp 内分段线性连续，平台与 ramp 接口只约束不向下，理论上仍可能向上跳变，也不保证一阶导数连续。 RMSE 与最大误差比较的是拟合 ramp 和原始实测温度，而不是平滑值。模型不会证明人工选择的 heat_start、heat_end 或时钟偏移正确，这些仍由研究者复核。

temperature_real→rolling median / mean→PAVA→pre + ramp + post 再保序→linear replay

默认 stdout 给研究者阅读

逐项解释输入、输出、实际参数与结果诊断，供研究者继续复核。

命令末尾显式加 --json 给机器消费

标准输出改为结构化记录；--json 本身不落盘，若只使用这一模式，调用者需要保存 stdout。三个拟合工件的路径不因此改变。

工件 职责 内容边界
temperature_fit.csv 给研究者逐行复核 比较记录温度、拟合温度与选区；它是审阅表，不是精确模型的替代品。
temperature_model.tpxmodel 给计算程序精确重载 使用可读 TOML 保存边界、模型类型、系数或插值节点；只放模型本体，不混入来源哈希、诊断或运行记录，也不使用 pickle。默认位于 experiment TOML 同级，canonical records/ 目录内的模型会被拒绝。
records/temperature_fit_record.json 给配对校验与审计 绑定 RGA/温控源、模型和审阅表的相对路径与 SHA256，并保存实际拟合参数、诊断、工具版本和 review_required。
记录 回答的问题 生命周期与消费者
temperature_fit_record.json 这套温度模型由哪些源字节、参数和诊断产生，并与哪张审阅表配对？ temperature fit 与三工件一起生成；供拟合审计读取，不是 temperature align 的计算输入。
TOML [[processing_record]] 某张正式信号表由什么输入、处理策略和父处理链产生？ align 成功写出 aligned.csv 后追加；记录实际 RGA、温控日志、.tpxmodel、信号输入与本次时钟/越界参数形成的 fingerprint。fit record 缺失或变化不使该计算谱系失效。
工作流 receipt.json 与日志 这次进程用什么 argv 启动，如何结束，stdout/stderr 和耗时是什么？ 成功、失败或取消的进程都可留下实例运行记录；科学 CLI 不把它当作模型配对清单或正式处理父链。
模型、哈希与科学接受是三件事

拟合只把研究者确认的温程关系固化为可重放模型。SHA256 一致只说明当前字节与记录相同；退出码为 0、fit record 可验证或 ProcessingRecord 已追加，都不会自动证明升温边界、模型误差、时钟偏移和对齐结果在科学上可接受。研究者仍须检查 CSV、诊断和 aligned.csv，再决定是否进入下一步。

COMMON STOP REASONS

停止写出，通常是在保护边界

模型不能安全重载
.tpxmodel 后缀、TOML schema、单位、边界或模型字段非法，或者模型位于 canonical records/ 目录时都会拒绝 align；重新选择经复核的模型本体。
RGA 或温控源不可用
检查 experiment TOML 中的当前路径、表格格式和时间范围；这些当前源字节会进入 alignment fingerprint，而不是与 fit record 进行门禁比较。
时间不递增或没有重叠
检查 RGA ms、温控分段、日期跨夜与 offset；不要靠 clip 掩盖无重叠。
输出文件已经存在
命令拒绝覆盖；选择新的输出路径，保留旧工件供比较。

RESEARCHER REVIEW

写出下一阶段输入前，检查七件事

  1. 01

    RGA 时间有效：ms 单调，Date/Time metadata 属于本次采集。

  2. 02

    温控分段合理：暂停、计数器重复与跨午夜没有压缩真实时间。

  3. 03

    容差有依据：记录为何采用本次 clock-elapsed 分段阈值。

  4. 04

    边界已复核：heat_start / heat_end 对应实际物理事件。

  5. 05

    offset 符号正确：正值让温度时钟后移；不要仅凭图形“看起来重合”。

  6. 06

    越界策略可解释：明确是否停、删行、保留缺失或使用端点。

  7. 07

    复核与审计分开看：fit CSV 用于人工检查，fit record 用于核对拟合来源、参数、诊断与输出哈希；它们缺失或变化不改变 .tpxmodel 的 align 计算，但审计不完整仍应明确报告，也不等于科研接受。
