GENERAL TABLE ALIGNMENT · NUMERIC / DATETIME

左表定行， 右表供值。

align_by_coordinate() 只做一件事：沿两张 DataFrame 各自声明的坐标，把右表一个或多个数值列线性插值到左表。它不会猜列、排序数据或替研究者选择越界行为。这是 Python SDK 算子，不是 temperature align 的双时钟与温程模型流程，也不再作为顶层 tpdtpd align CLI 暴露。

科学边界

线性插值只建立数值对应关系。两列是否代表可比较的物理坐标、单位是否一致、采样之间是否允许线性近似，仍由研究者确认。

先满足坐标契约，再谈插值

SDK 对 numeric 与 datetime 使用同一组明确约束；不会先排序、去重或默默修复输入。

类型一致
两侧都必须是 numeric，或两侧都是 datetime；timezone-aware 与 timezone-naive 也不能混用。
严格递增
左右坐标都不能倒退或重复。输入顺序就是被审查的数据事实。
右表最少两点
线性插值来源至少需要两个坐标点。
来源值有限
每个右表待插值列必须是 numeric，并且不含 NaN 或无穷值。
输入不原地修改
align_by_coordinate() 返回左表副本与诊断；调用者传入的 DataFrame 保持不变。
坐标 left[x_left] ↔ right[x_right]

同类、有限、严格递增。

映射 right_values = {source: output}

至少一个，输出名唯一。

结果 AlignmentResult(frame, diagnostics)

新表与本次边界诊断分开保存。

为什么 datetime 先减右表起点？

实现先把两侧坐标减去右表起点，再把 datetime 纳秒差换成秒后插值，避免把巨大绝对时间戳直接转成浮点数造成精度损失。

这一步只改善数值表示，不改变时区语义，也不会接受 aware / naive 混用。

运行前检查

  • 两侧坐标单位或 datetime 语义相同。
  • 坐标已经按实验事实严格递增。
  • 右表列确实允许线性插值。
  • 输出列名不会掩盖原始测量。

SDK 不恢复 CSV 类型；调用者必须先把两侧坐标准备为同类 numeric 或 datetime dtype，并自行确认物理语义。

02
02

越界不是细节，是输出语义

左表坐标落在右表范围之外时，四种策略会改变输出语义；SDK 默认严格报错，仅在复核覆盖关系后显式改用其他策略。

策略左表越界行插值列适合回答的问题
error不输出不输出所有左表行都必须有右表覆盖；最严格。
drop删除只计算范围内行只保留两侧共同坐标范围。
nan保留越界位置写 NaN保留左表形状，同时显式标出没有插值值。
clip保留使用最近右表端点值研究者明确接受端点常值延伸。

OverlapPolicy.REQUIRE

左右范围完全不相交时立即失败；这是 SDK 默认重叠策略。

OverlapPolicy.ALLOW_EMPTY

只允许继续应用越界策略。例如配合 drop 得到结构明确的空表；它不会自动取消 error。

默认不覆盖

省略覆盖选项时，输出名与左表已有列冲突就拒绝运行。

allow_overwrite=True

只在研究者明确要用插值值替换同名左表列时使用；左坐标列本身始终不能被覆盖。

不要混淆

clip 是端点常值，不是线性外推；nan 是明确缺失，不是 0；allow-empty 是无重叠许可，不是自动生成有意义的数据。

一个明确的 SDK 入口

SDK 接收调用者已经加载并准备好 dtype 的 DataFrame。通用 CSV 适配 CLI 已移除；插值与科学校验集中在 tpx.alignment，温程专用流程也复用这一个算子。

诊断说明复核用途
coordinate_kindnumeric 或 datetime确认实际解析类型。
left_rows / right_rows / output_rows两侧输入与输出行数识别 drop 是否改变行数。
out_of_bounds_rows左表越界点数量化边界影响。
left_range / right_range / overlap_range坐标范围与交集核对覆盖是否符合实验预期。
out_of_bounds_policy / overlap_policy本次实际策略让结果语义随报告可见。
查看真实调用路径

caller → tpx.alignment.align_by_coordinate() → AlignmentResult(frame, diagnostics)

tpdtpd temperature align 仍通过温程模型与双时钟专用流程调用这个 SDK 算子；它负责自己的文件、ProcessingRecord 与完成报告，不能由通用两表插值替代。

SDK 调用边界

  • right_values 的来源列和输出名都必须唯一。
  • SDK 不读取或写入 CSV，也不创建 ProcessingRecord；文件与谱系由具体调用者负责。
  • 越界默认 ERROR、重叠默认 REQUIRE，并默认拒绝覆盖左表已有列。
  • 坐标 dtype 必须由调用者显式准备，SDK 不提供 auto 类型恢复。
  • 返回值同时包含新的 DataFrame 副本和本次边界诊断。

完整参数以当前环境中 AlignmentSpec 与 align_by_coordinate() 的 Python API 为准。

常见拒绝是在保护什么

先修正表格契约或研究决定；不要靠排序、填零或改列名把错误藏起来。

alignment coordinate contains duplicates

同一个坐标对应多行，线性插值来源不再唯一。先回到采集或预处理决定如何处理重复点。

alignment coordinate must be strictly increasing

输入坐标倒退。函数不会自动排序，因为排序可能掩盖采集顺序或时钟重置。

coordinate types differ

一侧是 numeric、另一侧是 datetime。明确共同坐标后再运行，不做隐式单位转换。

point(s) fall outside the right range

当前选择了严格 error。检查范围后，只有研究者明确接受时才改用 drop、nan 或 clip。

output column(s) already exist in the left table

默认不覆盖左表已有列。为插值列使用新名字，或在确认覆盖语义后设置 allow_overwrite=True。
