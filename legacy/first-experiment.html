第一次检查一个 TPD 实验

先确认配置和两份原始文件可读，再决定下一步。这里不拟合、不扣本底，也不自动分析。

从第 1 步开始 返回首页

先准备两份原始文件

当前 checkout 要求 Python 3.11 或更高版本。原始数据无需复制进源码仓库；配置只记录它们的位置。

HAL RGA CSV

数据区至少包含 Time、ms 和一个质量通道；其他诊断列可以保留。

字段含义 / 单位
Date … Time …采集开始日期与 12 小时制时钟
TimeHAL 显示的经过时间文本
ms经过时间，ms；用于建立采集时间轴
含 mass 28 或 28_amu 的列名m/z 28 离子电流，A

真实 HAL 表头可以是 Scan 1 : mass 28.00；程序从列名识别 AMU，绝不按列位置猜测。

四列温控日志

无表头、Tab 分隔、固定四列；它的行数不必与 RGA 相同。

位置字段单位
1clockhh:mm:ss AM/PM
2elapsed_ss
3temperature_set°C
4temperature_real°C
先理解形状

RGA 是 NRGA 行、多质量通道的电流表；温控是 NT × 4。这里分别读取和概览，尚不把两条时间轴对齐。

创建 schema 4 配置

这一步只建立实验事实的骨架，不读取原始文件，也不推断目标物种。

只有确实测量过才增加 --mass-mg 35 或 --bet-m2-g 596。未知值应省略，不能填 0。

写入
一个新的 experiment.toml
不写入
原始 CSV、温控日志或任何处理产物
覆盖规则
默认拒绝已有目标；只有明确决定后才使用 --force
这条命令实际调用了什么？

tpdtpd → method_main → init.execute → write_experiment_config

CLI 负责参数与路径，tpx.config 负责写出严格的 schema 4 配置。

研究者检查

  • 实验名称能否唯一指向这次 TPD。
  • 两条相对路径是否指向对应原始文件。
  • 质量与 BET 是否来自真实独立测量。

新配置的 calibration 为空，reference 保留未审核状态；vacuum 保存当前 AMU→常数电流初值，后续可逐 AMU 审核 raw-bound 纯指数。fragmentation 写入显式 identity mapping，但它没有 pending / accept 状态，也不代表本实验已有碎片标定：先用 fragmentation show 检查，必要时由研究者执行 fragmentation set。默认仪器信息也应按实验事实核对。

02
02

检查配置、原始数据与必需通道

用同一个只读入口严格加载 TOML、读取 RGA 与温控文件，并按需核对下游明确要求的 AMU；成功不等于科学判断已经完成。

默认 1 s 到底是什么？

它是比较墙钟步长与 elapsed_s 步长、判断是否开启新时间重建分段的默认阈值。普通日志直接省略该参数；只有复核仪器计时特性后才覆盖，它不是固定科研常数。

默认：给人看

报告 schema、配置 SHA256、实验事实、两份数据概况，以及要求的通道是否均存在。

显式 --json：给机器

在同一命令末尾增加 --json，获得点数、实际与必需 AMU，以及完整机器字段。

命令返回 0 后，继续在同一份报告中人工复核；无需再运行第二个配置/数据检查入口。历史版本运行证据及其与当前接口的区别见运行证据页。

检查通过证明了什么，又没有证明什么？

它证明 schema、路径、时间轴和要求的 AMU 可读。RGA 读取只因无效 ms 丢行；单个电流格缺失不会自动让检查失败。

它不证明物种指认、本底、碎片矩阵、校准或实验选区正确。

研究者检查

  • 报告必须同时包含 RGA 与温控概况。
  • --require-mass 必须来自下一步真实需求；指定后应显示为 (present)。
  • 任一错误先回到原始记录，不静默排序或补零。

预期失败统一退出码 2、错误写入 stderr；空 stdout 不是有效结果。

03
03

人工复核同一份只读概况

第 2 步已经把配置事实与两份原始数据概况放在一起；这里审核同一份输出，不重复读取文件。

机器需要完整字段时，在命令末尾显式增加 --json。输出模式不会根据 TTY 或重定向自动改变。

这条只读命令经过哪些层？

config inspect → load_experiment_config → read_rga_csv + read_temperature_log → 人类报告或显式 JSON

两份表在这里各读取一次、分别概览；时间对齐属于后续独立命令。

研究者检查

  • 实验身份、样品实测属性与内标记录。
  • 实际 AMU、RGA 起始时间、时长和点数。
  • 温控点数与实测温度范围。
  • 校准审核状态与当前逐 AMU 真空模型；默认 identity fragmentation mapping 是否适用于本实验，必要时是否已由 fragmentation set 更新。

配置中的分析通道与 RGA 实际测得的 AMU 是两个集合，不能混为一谈。

你要亲自确认什么

  • 01实验身份

    名称、日期、样品和 TPD 方法都属于同一次实验。

  • 02实测属性

    质量与 BET 有记录才填写；未知保持缺失，不写成 0。

  • 03实际通道

    AMU 列表来自真实表头，并覆盖下一步所需信号。

  • 04时间尺度

    RGA 时长、点数与温控点数符合采集记录。

  • 05温度范围

    最低、最高实测温度与实验程序相符。

  • 06初始状态

    空 calibration、未审核 reference、当前 vacuum 电流映射，以及显式默认的 identity mapping 没有被误当成本实验测得、拟合或标定的结果。

常见错误怎么判断

错误信息是停止并检查事实的信号，不是绕过约束的理由。

Unsupported schema_version …; expected 4.

输入不是当前 schema 4。不要把历史 schema 或旧顶层 tpdtpd inspect 写成当前接口；应按原始实验记录建立当前配置。

RGA CSV does not exist / Temperature log does not exist

从 experiment.toml 所在目录检查相对路径、文件名与读取权限，而不是只看当前 shell 目录。

Cannot find Date/Time metadata or data header

HAL CSV 必须有 Date … Time … 元数据，数据头前两列必须是 Time, ms。

Duplicate m/z … columns / No mass channels found

检查质量列命名。每个识别出的 AMU 只能出现一次，且至少需要一个含 mass 数字 或 数字_amu 的列名。

RGA time is not monotonic

ms 发生倒退。回到原始采集文件判断拼接、重启或导出问题，不要静默排序。

Invalid clock value / 无法重建严格递增温控时间轴

检查四列顺序、Tab 分隔、12 小时制时钟，以及暂停或跨午夜记录；再按日志特征选择显式容差。

Required AMU channel(s) are missing from RGA data

--require-mass 指定的信号没有被真实采集。核对仪器设置；缺失通道不能写成 0 A。

参数组合或目标文件错误

--require-mass 必须是正整数且可重复；时钟容差通常保留默认值，只有已复核仪器日志特征后才覆盖。重复初始化默认拒绝覆盖，只有明确决定后才使用 --force。

确认事实之后，再选择下一步。

完成标准是“配置与数据可读，并已人工复核概况”，不是“分析已经自动完成”。
