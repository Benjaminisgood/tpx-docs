列名来自当前 SDK 映射，不按位置猜测。

缺失不是 0

曲线坐标和响应必须是有限数值；程序不会用 0 填补缺失。质量与 BET 必须是正的真实测量值：优先读取实验 TOML，也可由本次命令显式给出；若命令值与配置冲突，必须人工复核后加 --reviewed-sample-override。

normalize 实际经过哪些层？

tpdtpd normalize → normalize.execute → tpx.normalization.normalize_response → 新 CSV

输出保留规范坐标和绝对响应，再增加已请求的归一化列；其他无关输入列不会自动带入。

01
01

先审核分析基线：preview 后才 accept

integration baseline preview 把可复算定义以 pending 状态写入 experiment TOML，并生成只作记录/展示的 review JSON 与审核图；科研人员看过后，再用 integration baseline accept 核验同一 normalized 输入和定义指纹，并把状态改为 reviewed。两步都不写 CSV。

上例使用 CLI 默认 basename：review/accept JSON 进入 records/，审核图写在输入旁。只需更换输出目录时，保留 basename 并仅改父目录。

审核区间

reviewed_interval 表示真正用于审核模型的区间；这里的模型、取样和估计量由研究者决定。

完整程序显示

后续 integration peaks/areas 与 baseline-subtracted 绘图从 normalized 表和 reviewed 定义复算。正式面积越出审核范围时默认拒绝；只有显式 --allow-endpoint-held-extension 才承担端点保持外延风险。

术语为什么改

baseline-subtracted response 的中文是“基线扣除响应”：它准确说明“含基线响应 − 经审核分析基线”。旧称 baseline-corrected net response 同时使用 corrected 和 net，既冗余，也没有说明减去的究竟是哪一种基线。

vacuum、calibration background、response zeroing 和 integration baseline 是四个不同阶段，不能互相替代。

02

先看曲线：默认完整温程，并标注正式峰结果

plot response 只读取显式口径对应的 normalized 数据；默认 --display-range program 从程序零点画到第一次最高温，并在 normalized 输入与 TOML 指纹仍匹配时标注所有正式 Tmax/Tp 与当前 basis 面积。显示参数不会改写响应或平移零点。

默认保存

即使不写 --output，也会新建包含 target、response mode、basis 与 range 的唯一语义文件名；已有目标仍拒绝覆盖。

--show / --output

--show 在保存之外打开当前图形后端；--output 改用显式 PNG/PDF 路径。两者都不改变 CSV。

横坐标
默认 program 显示程序时间 ≥ 0 到第一次温度最高点的完整升温支路；analysis 读取 TOML baseline 的审核区间；custom 才接受成对温度边界
纵坐标
total 由 --basis 映射到 normalize 列；baseline-subtracted 从同一 normalized 表与 reviewed baseline 即时复算对应 basis
正式标注
默认读取同目标物种的 [peak_integration.*]，核验 normalized 输入 SHA-256 与 baseline 指纹；Tmax 是区间内最大积分响应采样点，只有 reviewed-explicit 才显示为 Tp
不改变
输入 CSV、响应数值和归一化结果；--no-annotate-integrations 只关闭标注
为什么没有“自动选择最好看的 basis”？

plot response → _verified_peak_annotations → _prepare_response_plot_frame → tpx.plotting.plot_response

total 列缺失时命令会报告当前可用 basis 和需要补做的归一化，而不是退回另一个纵轴。baseline-subtracted 读取同一 normalized 表，按 target 选择物种并使用 experiment TOML 中 reviewed baseline 复算；不读取 integration JSON，也不依赖历史扣基线 CSV。只有确需峰区裁图时才显式使用 custom。

研究者检查

  • 比较对象是否使用同一种 basis 与单位。
  • 质量或 BET 是否来自对应样品的实测记录。
  • 完整升温支路是否暴露了峰区外异常；需要裁图时是否另外保留完整图。
  • 每个标注是否来自正确物种、结果 ID 和局部审核基线。
  • 标题是否写清样品、物种、basis 与处理状态。

图像用于复核和交流，不是新的定量数据表。

算吸附量：温度选区，时间积分

integration areas 从指定 target 的 normalized 输入和 experiment TOML 中 reviewed baseline 即时复算 r(t)-b(t)；温度负责选区，面积沿程序时间计算。正式运行把结果、输入 SHA-256 与 baseline 指纹写入 [peak_integration.<result-id>]，详细逐点证据写入 records/<result-id>_areas.json。

选择轴 temperature_fit_c

用 °C 界定要归属给该事件的闭区间。

→
积分轴 program_time_min

用 min 对 µmol min−1 做梯形积分，结果是 µmol。

即时复算量积分是否使用保存位置
r(t)作为被积响应来源来自 normalized.csv
b(t)从响应中扣除定义与审核状态在 experiment TOML；逐点证据在 JSON
r(t)-b(t)是沿 program_time_min 积分；不另写派生 CSV

基线模型、来源和估计量只在 integration baseline preview 阶段选择；旧的顶层 integrate_peak_areas 与内联 --baseline* 语法已不再注册，请按本页统一命令族迁移。

preview 不发布

--preview 显示全部具名区间、暂算面积和范围警告，默认写 records/<result-id>_areas_review.json 与输入旁审核图，但不写 [peak_integration.*]。

正式 TOML + records JSON

[peak_integration.<result-id>] 保存各具名区间、Tmax/Tp 语义、绝对/质量/BET 面积、样品属性快照、normalized 输入 SHA-256 与 baseline 指纹；records/<result-id>_areas.json 保存逐点证据。正式模式也不生成 CSV。

--result-id 是必填的稳定 TOML 科学身份，不是文件名装饰。同一样品、同一 target 的多峰共享 reviewed baseline 时，在一次 areas 中共用一个 result ID 和多个具名区间；不同样品的 offset/baseline 不共享。JSON 默认在 records/，图片写在输入旁；不擅自加 fresh、final、v2 或时间戳。

积分如何保持与峰识别独立？

integration areas → normalized target selection → reviewed baseline recomputation → integrate_curve → TOML / records JSON

面积动作从不调用 integration peaks，也不读取候选谷底为正式边界。研究者把确认后的具名温区显式输入；--preview 不写正式结果。正式运行未给 --peak-position 时只记录实际积分范围内最大响应采样点，语义是 maximum-integration-response-sample（Tmax），不会把未审核候选升级为 Tp。

研究者必须选择

  • 事件归属的温区，而不是“看起来差不多”的全图范围。
  • 确认 normalized 输入字节、target 和 experiment TOML 中 reviewed baseline 的来源仍匹配。
  • 负值保留还是截零；两者会改变积分量。
  • 是否在请求的温度边界插值。
  • 实际质量，以及确有测量时的 BET。
  • 能区分物种、峰与分支的稳定结果 ID，以及峰位是否真的经过人工复核。

当前方法只有 trapezoid；它适用于不等间隔程序时间。

04

找峰温：先声明所有识别假设

integration peaks 从 normalized 表与已审核 baseline 即时复算指定 target 的基线扣除响应，再在自己的温区和参数下寻找候选峰；它不计算面积，也不做物种或机理归属。

  1. 01截取

    先按程序时间下限，再按温区保留曲线。

  2. 02平滑

    把请求的 °C 窗口按实际温度步长换算为点数。

  3. 03筛选

    按极性、峰高与最小温差选择候选。

  4. 04排序

    候选先按强度竞争，最终按峰温输出。

TOML 候选摘要

[integration_peaks.<result-id>] 保存候选的程序时间、峰温、分口径峰高和建议边界。所有建议都标为 unreviewed_candidate_not_used_for_integration。

records JSON + 审核图

records/<result-id>_peaks.json 保存逐点计算证据，输入旁审核图显示响应、基线、平滑结果和候选峰/谷底。显式 Gaussian seeds 可叠加探索性组件，但不输出面积；不生成峰表或曲线 CSV。

平滑结果会不会改变积分？

integration peaks → normalized target selection → reviewed baseline recomputation → tpx detect_peaks → TOML / records JSON

不会。平滑只属于候选峰计算证据与显示；integration areas 从同一 normalized 表和 reviewed baseline 独立复算，并使用研究者明确给出的积分温区与负值/边界规则。

研究者必须选择

  • 响应 basis，以及找正峰还是负峰。
  • 报告固定峰数，还是温区内全部候选。
  • 最小峰间温差和以 °C 表示的平滑窗口。
  • 绝对峰高阈值，或明确不用阈值。
  • 预期峰数不足时严格失败，还是先接受更少结果。

过小的非零平滑窗口或相对点数过宽的窗口都会被拒绝，而不是静默改成别的值。

比较实验：完整 total response，三种物理纵轴

plot comparison 把至少两套实验的完整 normalized total response 放进一张图；默认依次绘制 absolute、mass-umol 与 BET 三个 panel，并把各自局部基线得到的正式峰面积列在图底表格中。

absolute response_umol_min

µmol min−1；比较每份样品的绝对脱附速率

mass-umol response_umol_min_g

µmol min−1 g−1；消除样品质量差异

BET response_umol_min_m2

µmol min−1 m−2；按实测比表面积比较

完整横轴
每条曲线都先截取自己的完整升温支路；共享横轴取所有系列温区的并集，但曲线只画自己的实测范围，不向两端外推
数值显示
保留负值并画零参考线；样品用不同颜色、线型和 marker 区分，不把负值静默裁成 0
正式峰表
逐项列出样品、峰/特征、Tmax/Tp 语义、温度、µmol、µmol g−1 与 µmol m−2；面积来自各样品自己的 reviewed baseline，同一样品的多峰可共享
失败边界
默认任一系列缺质量、BET、所需响应列、正式积分或来源 SHA-256 匹配时整张图失败，不输出缺面板或缺峰的半成品；可重复 --basis 显式请求较少面板
为什么完整曲线和局部面积可以同图出现？

plot comparison → _resolve_response_display_range(program) → _verified_peak_annotations → tpx.plotting.plot_response_comparison

每个 panel 的曲线骨架是各实验完整 total response；峰位置和面积来自 experiment TOML 中对应的正式积分记录。baseline-subtracted 显示由各自 normalized 表与 reviewed baseline 即时复算，不存在可被延长后冒充整段净响应的局部派生 CSV。

外部 CLI 与 TPX 工作流

在终端运行 CLI 后，在 TPX 实验处理页面选定同一实验目录和 TOML，读取工件列表。工作流可发现目录中的图、CSV、模型和 JSON；图表预览与下载使用列出时的 SHA-256 核对当前文件。

目录发现的外部工件与工作流本次运行输出分开记录；有关联 ProcessingRecord 或运行记录且 SHA-256 一致，只能证明当前文件身份。绘图 CLI 会复核 [peak_integration.*] 记录的 normalized 输入哈希与 baseline 指纹；记录存在本身不代表工作流已重新执行或人工审核。目录发现、哈希通过和图像可见都不代表研究者已经科学审核并接受基线、区间、面积或机理解释。

不要把曲线、局部面积、候选峰和科学接受混成一个结论

  • 01纵轴 basis

    归一化只改变比较基准，绝对响应仍保留。

  • 02积分坐标

    温度负责选区，时间负责积分，单位才得到 µmol。

  • 03基线假设

    基线来源、负值和边界插值必须随结果一起复核。

  • 04位置语义

    integration peaks 候选不进入正式结果；默认积分位置只能称 Tmax，人工显式复核后才称 Tp。

  • 05正式峰结果

    正式面积摘要、normalized 输入 SHA-256 与 baseline 指纹写入 [peak_integration.<result-id>]；逐点证据写入 records/<result-id>_areas.json，不生成 integration summary/curve CSV。

  • 06比较口径

    完整 total response 负责展示全温程；面积来自各样品自己的 reviewed baseline，同一样品多峰可共享，不同样品不共享。

  • 07工作流边界

    外部文件可被目录发现并预览；“可见”“哈希一致”和“人工科学接受”是三个不同状态。

  • 08输出模式

    默认报告给人看；机器消费时在首次叶命令运行中显式增加 --json，不要为取得 JSON 重跑写操作。

常见错误怎么定位

先检查列、单位和参数组合，再判断科学假设；不要用改列名或填零绕过约束。

Response table is missing column(s): temperature_fit_c.

输入不是包含拟合温度的 rate.csv / normalized.csv 主表。积分或峰分析输出中的 temperature_c 不能冒充它。

normalized 输入与已审核 baseline 不匹配

正式面积、候选峰和基线扣除响应图都要求当前 normalized 输入 SHA-256、target 与 experiment TOML 中 reviewed baseline 的来源一致。records/*.json 只保存详细证据，不能替代 TOML 审核状态。

旧的内联基线参数被拒绝

旧顶层 integrate_peak_areas 已移除，integration areas 也不接受内联 --baseline*、--linear-on 或 --already-corrected。改为先运行 integration baseline preview，人工审核后再 integration baseline accept。

温度边界无法插值

请求边界必须位于实际温度范围内，温度坐标不能倒退；积分时间轴还必须严格递增。

平滑窗口点数不足

非零 °C 窗口会按实际温度步长换算成点数。窗口太小无法做局部二次平滑，窗口太大又可能超过当前温区的点数。

Response basis … is unavailable

输入没有该 basis 对应列。按错误提示用实测质量/BET 重新运行 normalize，不要自动退回另一纵轴。

正式峰结果的 normalized 输入或 baseline 指纹不一致

plot response 与 plot comparison 会重新核验 [peak_integration.*] 记录的 normalized 输入 SHA-256 和 baseline 指纹。恢复与 TOML 精确匹配的输入，或在重新审核局部基线和面积后发布新的唯一结果；不能只改 TOML 路径或跳过检查。

默认三面板比较因质量或 BET 缺失而失败

默认 absolute、mass-umol、BET 三面板要求每个系列都有真实样品质量、实测 BET、对应响应列和正式归一化面积。补齐并重新运行 normalize / integration areas，或明确重复 --basis 只请求当前科学问题需要的口径；程序不会用 0 填补或输出半张图。

输出文件已存在或与输入重名

阶段命令拒绝覆盖输入、已有目标和重复输出路径。优先使用 CLI 默认 basename；只需要换目录时，保留 basename 并仅改父目录。单样图默认名已包含 target、response mode、basis 与 range，integration JSON 默认在 records/；必填 result-id 使用已审核的稳定科学身份或最小职责型 ID，不擅自加版本或时间戳。

完整温程负责暴露问题，局部审核负责给出面积。

正式 TOML、三份来源哈希、单样图和三面板比较可以相互核对；TPX 工作流能展示这些工件，但最终科学接受仍由研究者明确完成。
