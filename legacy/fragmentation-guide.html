01

先读矩阵方向

矩阵不是一组可以交换位置的系数；行、列和输入表的顺序必须一致。

yi(t) = Σj Aij · xj(t)
yi(t)
第 i 个观测 m/z 在时间点 t 的离子电流，单位 A。
Aij
物种 j 对观测通道 i 的响应系数；来源和适用条件必须人工确认。
xj(t)
程序要求解的第 j 个物种电流，单位 A。
  1. 输入表 N 行 × 多列

    N 是时间或温度坐标上的数据点数。

  2. 观测数组 (N, K)

    K 个已配置且实际存在的观测通道。

  3. 线性求解 (K, K) @ (K, N)

    实现先转置，再调用 np.linalg.solve。

  4. 物种数组 (N, K)

    每一行仍对应原来的同一个数据点。

物理边界

数值求解只回答“在这张矩阵假设下，哪些物种电流能重建观测电流”。它不自动证明物种指认、系数来源或反应机理正确。

03

求解成功，不等于物理解释正确

先检查数值诊断，再判断物种归属。

condition_number
实际求解矩阵

SDK 对本次真正送入求解器的矩阵计算该值；available 模式下就是保留的主子矩阵。maximum_condition_number 只检查这个值；通过阈值也不等于物理模型正确。

configured_condition_number
原始完整矩阵

SDK 同时保留完整配置矩阵的条件数，便于与降维求解比较。只读 fragmentation show 中名为 condition_number 的字段也是这个完整矩阵含义。

solution_mode
求解范围

确认本次使用完整矩阵，还是显式删除配对行列后的主子矩阵。

ignored_coupling_max_abs
降维代价

只在部分求解时解释被忽略的耦合上限；值为零也不能替代实验判断。

负物种电流
需要解释，不自动裁零

可能来自配对缺失、噪声、基线、系数或模型外过程；SDK 保留求解值供复核。

DataFrame (N, M) → resolve_mass_signals → observed (N, K) → np.linalg.solve → FragmentationResult

先查看行列标签、系数、完整配置矩阵的条件数和来源；show 不读取也不求解信号表。

SDK 接收内存中的 DataFrame 与设置对象；它不读取 TOML，也不替你选择矩阵。纯 SDK 或无父记录 CLI 可以完成数值求解，但不会凭空获得 calibration / quantify 所需的 artifact role 与受控父链。

查看真实调用路径

SDK：tpx.fragmentation.correct_fragmentation() → resolve_mass_signals() → np.linalg.solve() → fragmentation_stage_frame() → FragmentationResult。

只读 CLI：tpxtpx.tpdtpd.fragmentation.execute() → load_experiment_config() → 输出矩阵与诊断。CLI 负责参数和文件适配，矩阵求解仍在 tpx SDK。

运行前后，逐项复核

  • 01行标签

    masses_amu 的顺序与实际观测列完全一致。

  • 02列标签

    species 的顺序与矩阵每一列的物种含义完全一致。

  • 03系数来源

    记录矩阵来自哪次标定、哪套仪器状态和哪些适用条件。

  • 04矩阵条件

    检查奇异性、条件数与自定上限；不要把“可求解”等同于“可信”。

  • 05缺失策略

    默认 error；若用 available，逐项查看跳过行列与被忽略耦合。

  • 06输出电流

    检查负值、异常幅度与可重建性；不要自动裁零或直接做物种归属。
